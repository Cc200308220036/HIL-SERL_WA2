### 4.3 安装过程中的 Livox 冲突

执行：

```bash
bash "$RUN"
```

该 `.run` 文件不是只安装 `upperlimb`，而是尝试安装14个 `zj_humanoid` 类型包。

基础镜像已经包含：

```text
livox-ros-driver2 1.2.0-1
```

安装器又尝试安装：

```text
zj-humanoid-ros-noetic-livox-ros-driver2 1.3.0-0focal
```

二者包含同一文件：

```text
/opt/ros/noetic/include/livox_ros_driver2/CustomMsg.h
```

因此 dpkg 报文件覆盖冲突。此时 `upperlimb` 等13个包已经解包，但状态为 `iU`，尚未配置。

没有采用以下高风险处理：

- 没有使用 `--force-overwrite`。
- 没有删除基础镜像现有的 Livox 驱动。
- 没有重复运行安装器。

## 5. ROS 环境叠加顺序修正

### 5.1 问题现象

类型包已经安装到：

```text
/opt/ros/noetic/share/upperlimb
/opt/ros/noetic/lib/python3/dist-packages/upperlimb
```

但按原顺序执行：

```bash
source /opt/ros/noetic/setup.bash
source /ros_noetic/catkin_ws/devel/setup.bash
```

之后仍然出现：

```text
[rospack] Error: package 'upperlimb' not found
ModuleNotFoundError: No module named 'upperlimb'
```

原因是第二个 `setup.bash` 将搜索路径重置为源码构建的 `/ros_noetic/catkin_ws`，隐藏了 `/opt/ros/noetic` 下新安装的类型包。

### 5.2 正确加载顺序

当前验证通过的顺序是：

```bash
source /opt/conda/etc/profile.d/conda.sh
conda activate hil-actor

source /ros_noetic/catkin_ws/devel/setup.bash
source /opt/ros/noetic/setup.bash --extend
```

合并后的关键路径：

```text
ROS_PACKAGE_PATH=
/opt/ros/noetic/share:/ros_noetic/catkin_ws/src

PYTHONPATH=
/opt/ros/noetic/lib/python3/dist-packages:
/ros_noetic/catkin_ws/devel/lib/python3/dist-packages

CMAKE_PREFIX_PATH=
/opt/ros/noetic:/ros_noetic/catkin_ws/devel
```

### 5.3 类型验收

### 8.2 测试脚本

测试文件：

```text
/root/catkin_ws/src/naviai_controller/scripts/test_0806.py
```

当前脚本逻辑：

```python
rospy.init_node("my_control_node")
ctrl = NaviController(model="wa2")

right_tcp_rt = ctrl.get_tcp_rt(ArmGroup.RIGHT)
right_tcp_rt[1] += 0.01
input("Press Enter to continue...")
ctrl.movel(right_tcp_rt, ArmGroup.RIGHT)
```

动作语义：

1. 使用 `RobotModel.WA2` 初始化控制器。
2. 读取右臂当前 TCP。
3. 在机器人基坐标系下将 Y 坐标增加 `0.01 m`。
4. 保持当前 TCP 姿态四元数不变。
5. 人工按回车确认后，通过 `movel()` 发送右臂绝对 TCP 目标。

### 8.3 结果

根据现场观察，脚本已经成功驱动真实机器人右臂运动。

今日由此验证了以下链路：

```text
hil-actor Python
  -> rospy
  -> naviai_controller
  -> upperlimb/MoveL Service
  -> WA2真实机器人
```

这证明基础 ROS 控制链路已经打通。

### 8.4 当前脚本的限制

`test_0806.py` 是临时功能验证脚本，尚不满足训练或无人值守运行要求：

- 未等待 TCP 首帧并检查 `None`。
- 未检查7维长度和数值有限性。
- 未检查目标工作空间。
- 未检查碰撞、奇异位形和软限位。
- 未显式设置低速 `v`、`acc`，使用控制器默认值。
- 未打印完整目标后进行二次审核。
- 未设置 Service 等待和动作完成总超时。
- 只依据调用和现场运动判断，尚未计算动作前后 TCP 误差。
- 未记录 Service 原始响应消息。
- 未实现异常时停止和失败恢复。

因此该脚本不能直接放入 HIL-SERL `step()`，也不能循环发送动作。

## 12. 下一步建议

下一阶段先停止继续扩大运动测试，优先将今日临时测试改为有明确门禁的验收脚本：

1. 独立只读状态测试，检查维度、有限值和超时。
