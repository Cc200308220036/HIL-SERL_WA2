### 1.4 任务成功的图像定义（人工快照，不是整条轨迹）

`bottle_pick` 一张 **成功图像** 必须同时满足：

1. 瓶子已被抓起并放到目标放置区；
2. 手爪已张开或已离开瓶子，瓶子稳定立在目标区；
3. 头相机能看到瓶子在目标区；腕相机能看到张开/离开后的近景（允许腕侧被桌面/瓶身占大部分）；
4. 操作员在该时刻按 `s` 快照，而不是把整局所有 step 标成功。

**失败图像**（按 `f` 快照）应覆盖 walkthrough 建议的 2～3× 负样本，至少包括：

- 空爪对着目标区；  
- 瓶子握在空中 / 工作空间各处；  
- 接近中、未放置；  
- 放到错误位置；  
- 半放置（靠近目标但未入区）；  
- 抓取未抬起、抬起后掉落。

禁止：把未按键的 step 自动写入失败包；禁止从 R11 `demo.pkl` 抽帧冒充。

## 2. 目标、非目标与 Action 控制权



### 2.1 目标

1. Actor 在 Orin 用 **zero policy + SpaceMouse** 采集成功/失败 **图像快照**（不是整条 R11 demo）；
2. 先 fake schema，再真机小规模 schema，再正式数量；
3. 样本按 **episode_id** 划分 train/val/test，同一轨迹不得跨集合；
4. Learner 在笔记本 `hil-learner` 训练二分类 Reward Classifier；
5. 测试集达到约定 precision / recall，并保存混淆矩阵与阈值；
6. checkpoint 拷回 Orin，Actor 能加载并对真实在线图像推理；
7. 抽查：Actor 输出的 succeed/reward 与人工标签一致；连续画面误触发率可接受；
8. 分类器输入 key / 分辨率 / crop 与训练完全一致；误判 **不得** 触发 reset / stop / unlock。



### 2.2 非目标

## 3. 可复用设计与冻结语义



### 3.1 数据流

```text
采集（Actor，classifier 不加载）
  policy = zeros(6)
      │
      ▼
  WA2SpacemouseIntervention + latch 50 Hz 积分
      │
      ▼
  操作员按键（tty，必须 Enter；不用 pynput）
      ├─ s → 把当前 obs 的 head/wrist 写入 success 列表
      ├─ f → 写入 failure 列表
      ├─ e → 结束本局并 R5 reset（本局快照保留）
      ├─ max_steps 到点 → 只提示，不 reset（继续 s/f）
      └─ Ctrl+C / 伺服故障 → stop+clear 或换局；已采快照仍落盘

拷贝
  只 scp 单个 classifier bundle（success.pkl + failure.pkl + sidecar）
  禁止拷 R11 demo.pkl，禁止拷 failed demo 轨迹

训练（Learner，fake_env，无 ROS）
  按 episode_id 划分 70 / 15 / 15
      │
      ▼
  create_classifier(image_keys=["head","wrist"])
  sigmoid BCE + 随机 crop（与上游 train_reward_classifier 一致）
      │
      ▼
  val 上选阈值（默认搜索，约束 precision）
  test 上报 precision / recall / 混淆矩阵
      │
      ▼
  classifier_ckpt/ + threshold.json + splits.json + metrics.json

在线抽查（Actor）
  load_classifier_func(checkpoint_path, image_keys=["head","wrist"])
  只打印 logit / p / succeed
  禁止 done|=succeed，禁止调用 reset / stop / unlock
```



### 3.2 分类器输入（与训练必须一致）


| 项                           | 冻结值                      | 说明                                                                        |
| --------------------------- | ------------------------ | ------------------------------------------------------------------------- |
| `classifier_keys`           | `("head", "wrist")`      | 与 policy 同 key；相机 YAML `classifier_prefer: wrist` 只是偏好，本任务放置区主要靠头相机，两路一起用 |
| 分辨率                         | `(1, 128, 128, 3)` uint8 | SERLObsWrapper + Chunking 之后                                              |
| crop                        | `null`                   | `head_wrist.yaml` 的 `classifier_crop` 本阶段保持 null，禁止训练时另切一块、推理时用全图         |
| proprio                     | 不输入分类器                   | 上游 `EncodingWrapper(use_proprio=False)`                                   |
| 嵌套 `observations["images"]` | 禁止入库                     | 必须已经是扁平 `head` / `wrist`                                                  |


以后若只留 `wrist`，必须**重新采集或至少重训**，旧 ckpt 作废。

### 3.3 图像包格式（给 `train_r12_reward_classifier.py`）

每个 bundle 目录：

```text
runs/wa2_bottle_pick/<R12_RUN_ID>/classifier/<bundle_name>/
  success.pkl          # list[sample]
  failure.pkl
  bundle.json
  SHA256SUMS
  episodes/*.json      # 每局 sidecar：episode_id、n_success、n_failure
```

每个 sample 只允许这些键（schema `r12-v1`）：

```text
episode_id: str
label:      int          # 1=success, 0=failure
index:      int          # 本局内第几张快照
created_at: str          # UTC
observations:
  head:  uint8 (1,128,128,3)
  wrist: uint8 (1,128,128,3)
```

禁止字段：`actions`、`next_observations`、`rewards`、`masks`、`dones`、`infos`、整段 R11 trajectory。  
训练脚本若发现 `observations["images"]` 或缺少 `head`/`wrist`，直接 FAIL。

`bundle.json` 至少含：

```text
schema_version            r12-v1
task_id                   bottle_pick
exp_name                  wa2_bottle_pick
n_success                 int
n_failure                 int
n_episodes                int
space_hash                必须 = 冻结值
config_bundle_hash        改 YAML 后的新值
classifier_keys           ["head","wrist"]
image_hw                  [128,128]
operator                  采集时传入
mode                      fake | live
```



### 3.4 数量与划分


| 包           | 成功快照     | 失败快照     | 最少 episode | 用途        |
| ----------- | -------- | -------- | ---------- | --------- |
| fake schema | ≥10      | ≥20      | 合成即可       | 管道        |
| live schema | ≥10      | ≥20      | 各 ≥3       | 真机 schema |
| live 正式     | **≥100** | **≥200** | 各 **≥10**  | 训练 Gate   |


划分（Learner 写 `splits.json`，禁止手工改 id 后重跑却不存档）：

```text
按 episode_id 分层随机
train : val : test = 70 : 15 : 15
同一 episode_id 的所有帧必须落在同一个 split
seed 固定 --split-seed 12
失败/成功分别分层，避免某一 split 全是正样本
```

禁止按「随机抽帧」划分（部署文档：避免同一轨迹跨集合泄漏）。

### 3.5 指标与阈值（任务约定）

上游只报 accuracy，**不够**。R12 约定：

```text
正类 = 成功图像（label=1）
阈值默认搜索空间   {0.50, 0.60, 0.70, 0.80, 0.85, 0.90, 0.95}
选阈值规则          在 val 上：precision >= 0.85 的候选里
                    最大化 precision 加权的 Fβ（β=0.5，更重视 precision），
                    同分再比更高阈值；避免为抬 recall 锁死 0.5，也避免
                    为追求极高阈值把 val recall 压到不可用
                    若都不满足：FAIL，补采难例，禁止只把阈值降到 0.5 过 Gate
test 硬指标         precision >= 0.85 且 recall >= 0.80
必须落盘            混淆矩阵 TN/FP/FN/TP、precision、recall、F1、accuracy、所选阈值
```

假阳性比假阴性更危险（会给错误 reward）。宁肯漏检，不要把「瓶子在空中」判成功。

在线抽查约定：

```text
人工标注 20 帧（成功/失败尽量各半，含难例）
逐帧与模型 succeed 对照，记录 FP/FN
再连续遥操 ≥30 s（不要求完成任务）
误触发：p>阈值 且人工认为未成功
可接受：连续误触发突发 < 3 次，且单次持续时间 < 0.5 s
不可接受：稳定把「握瓶在空中」判成功
```



### 3.6 Wrapper 失败封闭（相对 Franka 的硬改）

新建 `hilserl_wa2/wrappers/reward_classifier.py`：

```text
输入：load_classifier_func 返回的 logits、threshold、consecutive_n（默认 3）
输出：info["succeed"]、info["classifier_p"]、可选 reward∈{0,1}

禁止：
  terminated/done |= succeed
  调用 env.reset / request_reset
  调用 stop / unlock / clear
  改 actions / ServoL

连续帧：连续 consecutive_n 帧 p>threshold 才 succeed=True，避免单帧闪断
R12 eval 默认 --end-episode false（唯一允许值）
R13 若要 succeed→done，必须新开方案，不得在本 Gate 打开
```

`env_factory.py`：

```text
classifier=True 且 classifier_keys is None 且 mode=constant_zero
  → 仍 bypass（兼容 R8/R9/R10/R11 旧脚本）

  → 必须提供 checkpoint 目录（参数或 WA2_CLASSIFIER_CKPT）
  → 加载并包 WA2RewardClassifierWrapper(end_episode=False)
  → 缺 ckpt 则 FAIL，禁止静默 bypass

采集脚本 record_r12_success_fail.py 必须 classifier=False
```

`task_config.py`：


### 5.11.1 Step 7 FAIL 后：两端补数据与重训

> 更细的补数与干净重采命令见本节下文「路径 A / 路径 B」。  
> 后续只维护本方案文档；勿再另开 Step7 操作单副本。

#### 先读 FAIL 原因再采

| 打印 / 现象 | 优先补什么 | 禁止 |
| --- | --- | --- |
| `test_precision<0.85`（fp 多） | **难失败**：手投影仍在册子内、半放置、围瓶、运动中接近 | 只调低阈值；只堆「一眼空桌」失败 |
| `test_recall<0.80`（fn 多） | **干净成功**：瓶稳在册上，且头相机里**手投影完全退出册子外轮廓** | 把「手还在瓶旁」的 demo 结束态标成成功 |
| `val_constraint` | 与 precision 类似：val 上选不出 P≥0.85 的阈值 → 补难失败 | 手改 `threshold.json` |
| test 混淆矩阵全 0 / val 无成功 | **换局太少**（按 `episode_id` 划分）：多按 `e`，建议相关局 ≥10 | 同一局里狂采却几乎不换局，导致 test 空或 val 无正类 |
| 叠多轮 merged 后指标乱抖 | **干净重采**：新 `R12_RUN_ID` + 单包严标注，**不要**再并旧 merged | 无限 `merged_vN` |

标注铁律（补采 / 重采通用）：

```text
s 成功 = 瓶稳定立在小册子上 + 手的投影完全退出册子边缘
f 失败 = 手投影仍在册子内，或任意运动过程中画面
e     = 换局 reset（本局已采快照保留）
```

## 7. 常见故障与禁止绕过


| 现象                                              | 处理                                                     |
| ----------------------------------------------- | ------------------------------------------------------ |
| 直接跑 `record_success_fail.py` 空格无响应              | 预期；改用 `record_r12_success_fail.py` 的 tty `s`/`f`       |
| 接近过程全被标成失败                                      | 上游默认行为；WA2 禁止自动标未按键帧                                   |
| 把 R11 `demo.pkl` glob 进训练                       | FAIL；脚本须拒绝含 `actions`/`next_observations` 的包           |
| train accuracy 99%、test precision 0.4           | 泄漏或难例不足；查 `splits.json`，补负样本                           |
| 为过 Gate 把阈值降到 0.3                               | 禁止；走 §5.11.1 补难失败 / 干净成功，或干净重采                 |
| factory 一加载 ckpt 就 reset                        | Wrapper 误用了上游 `done or rew`；R12 必须 `end_episode=false` |
| `classifier_keys` 仍是 null，训练用 wrist、推理用 head    | FAIL；双端 YAML 与 `--image-keys` 必须同为 head,wrist          |
| 训练时随机 crop、推理时忘了同分布                             | 评估脚本与 `eval_r12_live` 均 `train=False` 全图；与上游 eval 一致   |
| 与 teleop 同时控臂                                   | 立即 stop；本局快照作废                                         |
| 推一会儿就 auto-reset，还没放到目标区                        | 旧逻辑把 `max_steps` truncated 当换局。现已只提示；换局只认你按的 `e`（伺服故障仍会换局） |
| `scp -r classifier/` 变成套娃目录                     | 只 scp **单个** bundle 目录                                 |
| 5588/5589 被占用                                   | 先停 R10 Server；R12 不准借用                                 |
| 用 SAC「试试分类器会不会给 reward」                         | 禁止；抽查 policy 只能 zero                                   |
| 把 `reward.mode` 改成 classifier 并让 R11 旧脚本挂上 ckpt | 禁止；采集必须 `classifier=False`                             |
| `config_bundle_hash` 与 R11 live20 对不上           | 预期（keys 已改）；只对齐 `space_hash`                           |
| 容器里 `pynput` / DISPLAY 报错                       | 不要装 X 键盘钩子；坚持 tty                                      |
