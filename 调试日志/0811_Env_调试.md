# WA2Env 功能与使用说明

> 适用工程：HIL-SERL × NaviAI WA2  
> 当前契约版本：`0.1.0`  
> 当前实现范围：WA2 左臂 6D TCP 连续控制

## 1. WA2Env 是什么

`WA2Env` 是 NaviAI WA2 机器人接入 HIL-SERL 的 Gymnasium 环境。它把机器人状态、图像占位观测、动作缩放、ServoL 控制和安全退出统一成标准的强化学习接口：

```python
observation, info = env.reset()
observation, reward, terminated, truncated, info = env.step(action)
env.close()
```

上层程序不需要直接操作 ROS ServoL 话题，只需向 `step()` 输入归一化动作。`WA2Env` 负责把动作转换成末端位姿增量，并通过安全会话发送给左臂。

当前设计规定：正式控制链中，`WA2Env` 是左臂 ServoL 的唯一动作出口。

```text
策略 / 人工干预
       │
       ▼
归一化 6D action
       │
       ▼
WA2Env：校验、限幅、状态检查、episode 约束
       │
       ▼
WA2ServoSession：位姿积分、ServoL、stop/clear
       │
       ▼
WA2 左臂
```

因此，不应在 `WA2Env` 控制机器人时，同时运行能够直接发布 ServoL 的 SpaceMouse 遥操脚本，否则两个控制源会竞争同一机械臂。

## 2. 实现组成

核心文件位于：

```text
catkin_ws/src/hilserl_wa2/
├── envs/
│   ├── wa2_env.py             # Gymnasium 环境入口
│   └── contracts.py           # 契约加载和 Gymnasium spaces
├── ros_adapters/
│   ├── state_monitor.py       # ROS 状态订阅、缓存和新鲜度检查
│   ├── servo_session.py       # ServoL 唯一发布者和安全生命周期
│   ├── mock_robot.py          # 无硬件状态与动作后端
│   └── mock_cameras.py        # 当前图像占位后端
└── configs/
    └── wa2_env_contract.yaml  # Env 默认加载的配置
```

各模块职责如下：

| 模块 | 职责 |
|---|---|
| `WA2Env` | 对外提供 `reset/step/close`，组织动作、观测和 episode 状态 |
| `WA2EnvContract` | 从 YAML 读取动作尺度、控制周期、观测形状和超时阈值 |
| `WA2StateMonitor` | 订阅左臂、灵巧手和控制器诊断状态，不发布动作 |
| `WA2ServoSession` | 设置 ServoL 参数、累计目标位姿、发布动作并负责安全停止 |
| `MockRobot` | 在内存中模拟 TCP 状态变化，供无 ROS 场景使用 |
| `MockCameras` | 保持 `head/wrist` 图像键和形状稳定，不打开真实相机 |

## 3. 三种运行模式

`WA2Env` 使用相同的 action space 和 observation space，支持三种运行方式。

| 模式 | 构造方式 | 状态来源 | 是否发送 ServoL | 用途 |
|---|---|---|---|---|
| Mock | `fake_env=True` | 内存中的 `MockRobot` | 否 | Learner、离线开发、接口联调 |
| ROS 只读 | `fake_env=False, read_only=True` | WA2 ROS 状态 | 否 | 读取真机状态、监控机器人 |
| ServoL 真机 | `fake_env=False, read_only=False` | WA2 ROS 状态 | 是 | 策略或脚本控制左臂 |

另有 `dry_run=True` 模式：连接真实 ROS 状态并计算目标位姿，但不设置或发布真实 ServoL 指令。它通常与 `fake_env=False, read_only=False` 一起使用。

构造函数主要参数：

```python
env = WA2Env(
    fake_env=True,
    read_only=True,
    dry_run=False,
    contract_path=None,
    seed=None,
    episode_trans_limit_m=0.03,
    episode_rot_limit_deg=5.0,
)
```

| 参数 | 含义 |
|---|---|
| `fake_env` | 是否完全使用内存后端；为 `True` 时不接触 ROS 和机器人 |
| `read_only` | 真机模式下是否只读取状态；为 `False` 才创建 ServoL 会话 |
| `dry_run` | 是否只计算动作结果而不实际发布 |
| `contract_path` | 指定另一份 Env 契约；不填时加载包内 YAML |
| `seed` | Mock 图像和 Gymnasium 随机数种子 |
| `episode_trans_limit_m` | TCP 相对本次会话起点允许的最大平移距离 |
| `episode_rot_limit_deg` | TCP 相对本次会话起点允许的最大旋转角 |

## 4. Action：怎样控制机器人

### 4.1 动作定义

动作是一个长度为 6 的 `float32` 数组：

```text
action = [dx, dy, dz, droll, dpitch, dyaw]
shape  = (6,)
range  = [-1, 1]
```

六个分量分别控制：

| 索引 | 分量 | 机器人运动 |
|---:|---|---|
| 0 | `dx` | TCP 沿基坐标系 X 平移 |
| 1 | `dy` | TCP 沿基坐标系 Y 平移 |
| 2 | `dz` | TCP 沿基坐标系 Z 平移 |
| 3 | `droll` | TCP 绕工具坐标系 X 旋转 |
| 4 | `dpitch` | TCP 绕工具坐标系 Y 旋转 |
| 5 | `dyaw` | TCP 绕工具坐标系 Z 旋转 |

正数表示正方向，负数表示反方向。例如：

```python
import numpy as np

move_x_positive = np.array([ 1, 0, 0, 0, 0, 0], dtype=np.float32)
move_y_negative = np.array([ 0,-1, 0, 0, 0, 0], dtype=np.float32)
move_z_positive = np.array([ 0, 0, 1, 0, 0, 0], dtype=np.float32)
roll_positive   = np.array([ 0, 0, 0, 1, 0, 0], dtype=np.float32)
pitch_negative  = np.array([ 0, 0, 0, 0,-1, 0], dtype=np.float32)
yaw_positive    = np.array([ 0, 0, 0, 0, 0, 1], dtype=np.float32)
hold_position   = np.zeros(6, dtype=np.float32)
```

### 4.2 从归一化动作到物理运动

默认每次 `step()` 的最大增量为：

```text
平移：action[:3] × 0.001 m
旋转：action[3:] × 0.25°
```

因此：

- `dx=1.0` 表示本步期望沿基坐标系 +X 移动 1 mm；
- `dx=0.5` 表示本步期望沿 +X 移动 0.5 mm；
- `droll=-1.0` 表示本步期望绕工具 X 轴旋转 -0.25°；
- 连续调用 20 次 `[1,0,0,0,0,0]`，理论累计目标为 +X 20 mm。

平移向量和旋转向量还会分别进行模长限幅。比如 `[1,1,0,0,0,0]` 不会在 X、Y 各移动 1 mm，而会按方向等比例缩放，使本步合位移不超过 1 mm。平移与旋转是两组独立限幅，因此同一步可以同时包含平移和旋转。

动作超出 `[-1,1]` 时会被裁剪；shape 不是 `(6,)`，或包含 NaN/Inf 时，Env 会拒绝该动作。

### 4.3 坐标系与姿态积分

- 平移使用机器人基坐标系：目标 xyz 直接加到当前命令位姿上；
- 旋转使用工具坐标系：增量旋转右乘当前姿态；
- TCP 姿态使用四元数 `quat_xyzw`；
- 真机命令从上一个命令目标继续累计，而不是每一步重新从测量位姿开始，因此可以形成连续轨迹。

“工具坐标系旋转”意味着机械手已经倾斜后，roll、pitch、yaw 仍围绕当前末端自身的 X、Y、Z 轴旋转，适合完成翻转和姿态调整。

### 4.4 运动幅度和速度

`WA2Env.step()` 本身不会 `sleep`，调用方必须维持控制节拍。契约目标周期为：

```text
control_hz = 50 Hz
control_dt = 0.02 s
```

在连续满幅动作且调用频率确实为 50 Hz 时，对应的名义增量速率约为：

```text
平移：1 mm/step × 50 step/s = 50 mm/s
旋转：0.25°/step × 50 step/s = 12.5°/s
```

这只是命令侧名义值，实际运动还受机器人控制器、跟踪误差和上层循环稳定性影响。控制运动强度时，优先调整 action 大小和调用频率，不应在未评估安全范围前直接扩大契约中的单步上限。

## 5. Observation：Env 能读取什么

`WA2Env` 返回嵌套字典，包含机器人状态和两个固定图像键：

```python
observation = {
    "state": {
        "tcp_pose":    float32[7],
        "tcp_vel":     float32[6],
        "joint_pos":   float32[8],
        "hand_joints": float32[6],
    },
    "images": {
        "head":  uint8[128, 128, 3],
        "wrist": uint8[128, 128, 3],
    },
}
```

### 5.1 状态字段

| 字段 | 含义 | 单位/格式 |
|---|---|---|
| `tcp_pose` | 左臂末端位置与姿态 | `[x,y,z,qx,qy,qz,qw]`，m + quat xyzw |
| `tcp_vel` | 左臂末端线速度与角速度 | `[vx,vy,vz,wx,wy,wz]`，m/s + rad/s |
| `joint_pos` | 左臂 8 个关节角 | rad |
| `hand_joints` | 左手 6 个关节状态 | rad |

左臂关节固定顺序：

```text
Chest_Z_L, Shoulder_Y_L, Shoulder_X_L, Shoulder_Z_L,
Elbow_L, Wrist_Z_L, Wrist_Y_L, Wrist_X_L
```

左手状态固定顺序：

```text
THUMB_MP_LEFT, THUMB_CMC_LEFT, INDEX_MCP_LEFT,
MIDDLE_MCP_LEFT, RING_MCP_LEFT, LITTLE_MCP_LEFT
```

状态来自以下 ROS 话题：

| 状态 | ROS 话题 |
|---|---|
| TCP 位姿 | `/zj_humanoid/upperlimb/tcp_pose/left_arm` |
| TCP 速度 | `/zj_humanoid/upperlimb/tcp_speed/dual_arm` 的 `left_arm` 字段 |
| 左臂关节 | `/zj_humanoid/upperlimb/joint_states` |
| 左手关节 | `/zj_humanoid/hand/joint_states` |
| 奇异与控制器状态 | `/zj_humanoid/upperlimb/uplimb_state` |

### 5.2 图像字段的当前状态

Env 已冻结 `head` 和 `wrist` 两个图像键，以保证 Actor 和 Learner 的 observation space 始终一致。不过当前 `WA2Env` 仍统一使用 `MockCameras`：

- 未指定 seed 时，头部图像是零图；指定 seed 时为确定性灰度图案；
- 腕部图像始终为零图；
- 当前 Env 尚未把真实 RealSense 图像送入 observation。

因此现阶段可以使用机器人状态控制左臂，但不能把 `observation["images"]` 当作真实相机数据。真实相机接入后仍将保持 `uint8[128,128,3]` 的接口形状。

## 6. `info`：运行状态和诊断信息

`info` 用于记录本步动作是否发布、机器人状态是否健康以及命令跟踪情况。常用字段包括：

| 字段 | 含义 |
|---|---|
| `is_singular` | 左臂当前是否处于奇异状态 |
| `state_age` / `ages` | 状态数据年龄 |
| `stale` / `stale_fields` | 是否存在超过 0.2 s 的状态字段 |
| `cmd_num` / `cmd_name` | WA2 控制器命令状态 |
| `iddp_status` | 控制器诊断状态 |
| `fake_env` / `read_only` / `dry_run` | 当前 Env 运行模式 |
| `delta_pos_m` / `delta_rot_rad` | 本步实际采用的平移/旋转增量模长 |
| `delta_pos_xyz` / `delta_rot_rpy` | 本步采用的各轴增量 |
| `action_clipped` | 裁剪后的归一化动作 |
| `published` | 本步是否真正发布 ServoL |
| `cmd_tcp` / `meas_tcp` | 命令 TCP 与当前测量 TCP |
| `tracking_err_m` / `tracking_err_rad` | 命令与测量之间的跟踪误差 |
| `servo_faulted` / `servo_health` | ServoL 会话故障和健康信息 |
| `step_count` | 当前 episode 已执行步数 |

只读模式下还会返回 `action_ignored_for_motion=True`，表示动作经过格式校验，但没有用于机器人运动。

## 7. Env 生命周期

### 7.1 `reset()`

```python
observation, info = env.reset(options={"ready_timeout_s": 8.0})
```

不同模式中的行为：

- Mock：恢复内存中的默认状态，或采用 `options` 指定的 Mock 初值；
- ROS 只读：启动状态订阅，并等待各状态字段就绪且新鲜；
- 真机 ServoL：在状态就绪后创建新的 ServoL 会话，以当前 TCP 为命令起点和 episode 安全边界原点。

当前真机 `reset()` 不会自动把机械臂移动到 home，也没有执行契约中预留的人工初始位姿容差校验。操作者需要先把机械臂置于合适、非奇异且无碰撞风险的起始姿态，再调用 `reset()`。

### 7.2 `step(action)`

一次 `step()` 的处理顺序为：

```text
动作 shape/有限值校验
→ 裁剪到 [-1,1]
→ 检查状态新鲜度和奇异状态
→ 计算平移与旋转增量
→ 检查相对 episode 起点的运动范围
→ 发布 ServoL（仅真机模式）
→ 读取最新状态并组织 observation/info
```

返回值含义：

```python
observation, reward, terminated, truncated, info = env.step(action)
```

- `reward` 当前恒为 `0.0`，等待后续接入任务奖励或 reward classifier；
- `terminated` 当前不负责自动判断任务成功，通常为 `False`；
- `truncated` 表示因最大步数、状态超时、安全故障或 episode 范围等原因需要结束当前 episode。

默认一个 episode 最多执行 400 步。

### 7.3 `close()`

```python
env.close()
```

真机模式下，`close()` 会依次调用：

```text
stop → clear_servo_params → 停止状态订阅
```

应用程序应始终通过 `try/finally` 保证退出时执行 `close()`。

## 8. 使用方法

### 8.1 容器环境准备

在 Orin 上进入容器并加载环境：

```bash
docker exec -it hilserl bash
source /opt/conda/etc/profile.d/conda.sh
conda activate hil-actor
source /ros_noetic/catkin_ws/devel/setup.bash
source /opt/ros/noetic/setup.bash --extend
source /root/catkin_ws/devel/setup.bash
export PYTHONPATH=/root/catkin_ws/src:$PYTHONPATH
cd /root/catkin_ws
```

### 8.2 Mock 模式

Mock 模式不会连接 ROS 或机器人：

```python
import numpy as np
from hilserl_wa2.envs.wa2_env import WA2Env

env = WA2Env(fake_env=True, seed=0)
try:
    obs, info = env.reset()
    action = np.array([1, 0, 0, 0, 0, 0], dtype=np.float32)
    obs, reward, terminated, truncated, info = env.step(action)
    print(obs["state"]["tcp_pose"])
finally:
    env.close()
```

### 8.3 ROS 只读模式

只读取 WA2 状态，不允许机械臂运动：

```python
import numpy as np
from hilserl_wa2.envs.wa2_env import WA2Env

env = WA2Env(fake_env=False, read_only=True)
try:
    obs, info = env.reset(options={"ready_timeout_s": 8.0})
    obs, reward, terminated, truncated, info = env.step(
        np.zeros(6, dtype=np.float32)
    )
    print("tcp_pose:", obs["state"]["tcp_pose"])
    print("hand_joints:", obs["state"]["hand_joints"])
finally:
    env.close()
```

### 8.4 真机 ServoL 控制

真机运动需要显式确认变量：

```bash
export R4_CONFIRM=YES
```

最小控制程序：

```python
import time
import numpy as np
from hilserl_wa2.envs.wa2_env import WA2Env

env = WA2Env(
    fake_env=False,
    read_only=False,
    dry_run=False,
    episode_trans_limit_m=0.03,
    episode_rot_limit_deg=5.0,
)

try:
    obs, info = env.reset(options={"ready_timeout_s": 8.0})

    # 沿基坐标系 +X 连续移动；每步最多 1 mm。
    action = np.array([1, 0, 0, 0, 0, 0], dtype=np.float32)
    for _ in range(10):
        obs, reward, terminated, truncated, info = env.step(action)
        if terminated or truncated:
            print("episode stopped:", info)
            break
        time.sleep(0.02)  # 调用方维持约 50 Hz
finally:
    env.close()
```

开始真机控制前必须确认：

- 物理急停可立即触达；
- 左臂工作空间无人员和障碍物；
- 当前姿态不是奇异状态；
- 没有运行 SpaceMouse 直连 ServoL 或其他机械臂控制节点；
- 程序包含可靠的 `finally: env.close()`；
- action、循环次数和 episode 限制与现场安全空间匹配。

## 9. 安全机制

当前实现提供以下软件安全边界：

1. 未设置 `R4_CONFIRM=YES` 时，拒绝启动真实 ServoL 会话；
2. 每步平移模长不超过 1 mm，旋转模长不超过 0.25°；
3. 默认相对会话起点的平移距离不超过 3 cm，姿态差不超过 5°；
4. 任一关键状态超过 0.2 s 未更新时，动作链进入故障停止；
5. 检测到左臂奇异状态时，不发送新动作并执行停止；
6. ServoL 应只有 `WA2ServoSession` 一个发布者；
7. 正常关闭、异常退出和进程结束路径均尽可能执行 `stop` 和 `clear_servo_params`。

软件保护不能替代物理急停、碰撞检查和现场监护。

## 10. 当前可控范围与尚未包含的功能

当前 `WA2Env` 能够完成：

- 读取左臂 TCP 位姿、TCP 速度和 8 关节位置；
- 读取左手 6 个关节状态；
- 控制左臂 TCP 沿基坐标系 X/Y/Z 平移；
- 控制末端绕工具坐标系 roll/pitch/yaw 旋转；
- 同时组合平移和旋转，形成 6D 末端轨迹；
- 监控状态新鲜度、奇异状态、动作发布和跟踪误差；
- 在关闭或故障时停止并清除 ServoL 参数。

当前版本尚未包含：

- 灵巧手抓握/释放动作。`hand_joints` 目前只读，6D action 不包含手部维度；
- 自动 MoveJ home 或完整的人工起始位姿容差确认；
- 真实头部和腕部相机 observation；
- 任务成功判定和真实 reward；
- 双臂同时控制；
- SpaceMouse 作为 HIL-SERL `intervene_action` 的正式接入。

如需灵巧手控制，应在后续明确冻结手部 action 语义，再扩展为独立手部控制通道或 7D action；不应把现有按钮 toggle 行为直接隐式塞入 6D action。

## 11. 配置维护

Env 契约有两份 YAML：

```text
configs/experiments/wa2_env_contract.yaml
catkin_ws/src/hilserl_wa2/configs/wa2_env_contract.yaml
```

仓库根目录版本是项目配置的权威副本；包内版本是容器运行时默认读取的副本。修改动作尺度、控制频率、观测形状或 topic 时，应同步更新两份文件并提升契约版本，避免 Actor、Learner 和真机 Env 使用不同接口。

最常调整的字段：

| 配置 | 当前值 | 作用 |
|---|---:|---|
| `action.max_pos_delta_m` | `0.001` | 单步最大平移 |
| `action.max_rot_delta_deg` | `0.25` | 单步最大旋转 |
| `action.control_hz` | `50` | 目标控制频率 |
| `action.control_dt` | `0.02` | 名义控制周期 |
| `freshness.state_max_age_s` | `0.2` | 状态过期门限 |
| `episode.max_steps` | `400` | episode 最大步数 |
| `control.servo_time` | `0.02` | WA2 ServoL 参数 |
| `control.servo_gain` | `800` | WA2 ServoL 增益 |

`episode_trans_limit_m` 和 `episode_rot_limit_deg` 当前是构造参数，不在 YAML 中；实例化 Env 时可针对任务缩小，但扩大前必须重新确认工作空间和安全风险。

## 12. 总结

`WA2Env` 已经把 WA2 左臂封装为统一的 Gymnasium 6D 末端控制环境。上层只需输出 `[-1,1]` 范围内的平移与旋转动作，就可以通过同一接口在 Mock、真机只读和 ServoL 控制模式之间切换。

使用时需要牢记四点：

1. 当前只控制左臂 TCP，不控制灵巧手；
2. 平移在 base 坐标系，旋转在 tool 坐标系；
3. `step()` 不负责循环定时，50 Hz 节拍由调用方维持；
4. 真机控制必须保持唯一 ServoL 发布者，并始终在退出时调用 `close()`。
