## 4. 关键阻塞：当前 SDK 没有可用 SpeedL

### 4.1 原方案假设

早期文档与 `spacemouse_wa2_teleop.py` 第一版假设：

```text
enable_speedl() + speedl() → /zj_humanoid/upperlimb/speedl/left_arm
```

### 4.2 实测结论（SDK 1.3.2）

```text
/zj_humanoid/upperlimb/enable_speedl     → 不存在
/zj_humanoid/upperlimb/speedl/left_arm   → 机器人节点未订阅
```

机器人实际公开的连续控制候选：

```text
/zj_humanoid/upperlimb/servol/left_arm   upperlimb/DualPose
/zj_humanoid/upperlimb/set_servo_params  upperlimb/Servo
/zj_humanoid/upperlimb/clear_servo_params
/zj_humanoid/upperlimb/stop
/zj_humanoid/upperlimb/speedj/...
/zj_humanoid/upperlimb/servoj/...
```

因此：**不能继续按 SpeedL 做实机遥控**；Python 能 import `SpeedL` 只说明类型包有定义，不代表运行中节点支持。

### 4.3 文档与脚本调整

- `docs/SpaceMouse_WA2.md`：标记 Gate G 未通过，禁止原 SpeedL Gate H。
- 遥控执行层后续改为 **ServoL 绝对位姿积分**。

## 5. naviai_controller 增加 ServoL 封装

### 5.1 代码改动要点

文件：

- `catkin_ws/src/naviai_controller/src/naviai_controller/core/arm.py`
- `catkin_ws/src/naviai_controller/src/naviai_controller/naviai_controller.py`

新增 / 完善：

- `servol(pose, arm)`：向 `servol/{left,right,dual}_arm` 发 `DualPose`
- `set_servo_params(time, gain, arm)`
- `clear_servo_params()`
- `stop()` → `/zj_humanoid/upperlimb/stop`

安全校验：

- 位姿长度、有限数、四元数非零且近似单位模长
- 当前仅允许已验证组合：`time=0.02`、`gain=800`
- 删除未使用的 `servol(..., acc=...)` 误导参数

### 5.2 问题：`set_servo_params` 默认失败

首次 Gate3 调用：

```text
设置伺服参数失败: The arm type is invalid for the current robot model.
```

原因：`ServoRequest.arm_type` 默认为 `0`，SDK 拒绝。

实测合法值：

```text
arm_type = 1 (LEFT) / 2 (RIGHT) / 3 (DUAL) → success
arm_type = 0 → fail
```

改进：`set_servo_params` 增加 `arm` 参数，默认 `ArmGroup.LEFT`，请求中写入 `req.arm_type = arm.value`。

### 5.3 官方文档与真机类型不一致

在线 SDK 文档部分写法为 `geometry_msgs/Pose`，真机 Subscriber 类型为：

```text
upperlimb/DualPose
```

以真机为准：单左臂时填充 `left_arm_pose`，发布到 `servol/left_arm`。

## 7. SpaceMouse 遥控脚本改造（重点）

### 7.1 旧实现问题

`spacemouse_wa2_teleop.py` 初版：

1. 依赖不可用的 `enable_speedl` / `speedl`。
2. 早期版本曾缺少真正生效的 `axis_enable`（参数传入被忽略）。
3. 速度指令语义与当前 SDK 不匹配。

### 7.2 新实现要点

文件：

```text
catkin_ws/src/hilserl_wa2/interventions/spacemouse_wa2_teleop.py
```

行为：

1. 订阅 `/spacenav/joy`。
2. deadman 按下上升沿：用最新左臂 TCP 初始化目标，避免跳变。
3. 按 `delta = velocity * dt` 积分平移目标；姿态本阶段固定。
4. `axis_enable` 强制关闭未验收轴；旋转轴禁止开放。
5. 限制：`max_dt`、`max_step_m`、`workspace_m`、`linear_scale` 上限。
6. 松手 / Joy 超时 / 退出：`stop()` + `clear_servo_params()`。
7. `_execute:=false` 时只打印目标位姿（dry-run）。

### 7.3 Gate6 / Gate7 验收摘要

Gate6 dry-run：

- 无 deadman 不累计
- 仅 X enable 时 Y/Z 不积分
- 松手冻结目标
- watchdog 约 0.25 s 内过期

Gate7 合成 Joy 实机（约 0.5 s 推动，5 mm/s）：

```text
X：约 +2.4 mm / 次，连续 3 次 PASS
Y：约 +2.4 mm PASS
Z：约 +2.4 mm PASS
松手后漂移 ≈ 0
```

### 7.4 问题：物理遥控“几乎不动”

用户按文档保守指令：

```text
_linear_scale:=0.005   # 仅 5 mm/s
```

再叠加默认：

```text
max_step_m = 0.0005 m
workspace_m = 0.02 m
```

体感只有轻微移动。

改进：

1. 将 `linear_scale` 硬上限由 `0.005` 放宽到 `0.03` m/s，并限制 `max_step_m≤0.002`、`workspace_m≤0.10`。
2. 编写 `docs/SpaceMouse使用指南.md`，给出保守 / 日常 / 较大范围三档调参，说明应同时调：

```text
_linear_scale
_max_step_m
_workspace_m
_deadzone
_axis_enable
```

推荐日常起步档示例：

```text
_linear_scale:=0.015
_max_step_m:=0.001
_workspace_m:=0.05
_axis_enable:="[1,0,0,0,0,0]"
```
