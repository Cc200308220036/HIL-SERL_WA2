## 6. HIL-SERL源码安装

HIL-SERL源码通过宿主机挂载直接提供给容器，不再复制一份源码到容器可写层。

`serl_launcher` 使用editable模式安装：

```bash
python -m pip install --no-deps -e \
  /root/catkin_ws/src/hil-serl-main/serl_launcher
```

使用 `--no-deps` 的原因：

- 防止安装错误的 `zmq` 包，应使用 `pyzmq`。
- Python 3.10已内置 `typing`，不应安装旧版backport。
- 防止从Git重新安装未修正的Agentlace。
- 防止pip覆盖已经验收的JAX、NumPy和OpenCV版本。

已修正独立源码中 `serl_launcher/setup.py` 的依赖元数据：

```text
zmq       → pyzmq
移除 typing
Git Agentlace → agentlace==0.1.3
```

该修改只发生在 `/home/naviai/hilserl_orin` 独立副本，不影响 `/home/naviai/ros_docker_test`。

## 7. 调试问题与解决结果

### 7.1 `docker cp` 无法复制文件

现象：

```text
Error response from daemon:
openat usr/lib/aarch64-linux-gnu/libcudnn_*.so.9.3.0:
read-only file system
```

原因：

容器存在多个只读cuDNN bind mount，`docker cp` 在daemon归档/解包阶段受到这些挂载影响。虽然终端短暂显示复制成功，最终文件并未保留。

处理：

改用标准输入直接向容器目标文件写入：

```bash
docker exec -i hilserl sh -c \
  'cat > /opt/hilserl/目标文件' < 宿主机源文件
```

最终依赖锁、Agentlace wheel和验收脚本均成功写入容器。

### 7.2 TF-Keras缺失

现象：

```text
ModuleNotFoundError: No module named 'tf_keras'
```

处理：

安装与TensorFlow对应的版本：

```text
tensorflow==2.21.0
tf-keras==2.21.0
```

### 7.3 TensorFlow与JAX重复注册XLA protobuf

现象：

```text
File already exists in database: xla/xla_data.proto
Check failed: GeneratedDatabase()->Add(...)
Aborted (core dumped)
```

原因：

先导入TF-Keras/TensorFlow，再导入JAX相关模块时，两套XLA组件会重复注册同名protobuf描述。

处理：

同一Python进程中必须先导入JAX，再导入TensorFlow相关模块：

```python
import jax
import tensorflow
import tf_keras
import tensorflow_probability
import distrax
```

HIL-SERL当前 `train_rlpd.py` 本身先导入JAX，符合该顺序。

### 7.4 `serl_launcher` 的错误依赖声明

现象：

```text
serl-launcher 0.1.2 requires typing
serl-launcher 0.1.2 requires zmq
```

处理：

修正 `setup.py` 后重新执行editable安装。最终：

```text

```

## 11. 环境保存注意事项

当前 `hil-actor` 是在运行中的容器可写层里手工创建的：

- `docker stop` / `docker start`：环境会保留。
- 删除并重建容器：环境会丢失。
- `docker compose down` 后重新创建：需要重新安装环境。

在WA2真机全流程验收完成后，再将最终版本、修正项和安装步骤固化到 `Dockerfile.hilserl`，构建可重复部署的新镜像。
