## 1. 问题定位（0817 已证实）

独立遥操顺、Actor recorder 卡，不是 SpaceMouse 映射算错（主轴滞回已另修），而是 **采集把「积分 + 发指令」绑在整步 `env.step` 上**。

### 1.1 改 hold-last 之前

| 项目 | 遥操 | 采集 |
|---|---|---|
| 循环 | 固定 50 Hz + `rate.sleep()` | `while env.step()` 能跑多快就多快 |
| 每拍 | 读杆 → 按 **dt 积分** → `servol` | 积分 1 mm、ServoL、双相机 720p decode/resize、组 transition |
| 实测周期 | ≈20 ms | **50～140 ms**（约 7～20 Hz） |
| 固件 | `set_servo_params(0.02, 800)` 按 20 ms 等指令 | 指令流不规则 → 顿挫，严重时 `PROTECTED` |

夹爪走 `request_hand` / `joint_switch`，不经 ServoL。因此会出现：**手臂停在保护态，夹爪还能开合**。`UplimbState.cmd_num=15` / `cmd_name=PROTECTED` 不在 SDK `CmdState`（只到 `SERVOL=14`）里。

次要：rospy 回调里做 720p→128 抢 GIL；CTRL `dt>45ms` 几乎每步打印进一步拖慢。

### 1.2 主轴抢轴（已修，与 Servo 周期正交）

标定右移 |Y|−|Z|≈0.13，旧 `axis_switch_hysteresis=0.10` 导致抢轴并 `filtered.fill(0)`。已改为滞回 **0.25**、换轴不清滤波、`secondary_axis_ratio=0.90`。平移 XOR 旋转组锁保留。明天第二刀**不要**为了「更顺」拆掉组锁，除非现场再标定。

## 2. 已落实：第一刀（位置保持线程）

**一句话：** 50 Hz 线程反复发送**当前目标位姿**；`env.step` 仍负责把杆量积成 1 mm。这是 **hold-last 位姿**，不是遥操那种 **按时间积分速度**。

```text
Joy / policy
    │  每 env.step 最多 1 mm / 0.25°
    ▼
apply_normalized_action ──► 写入 _cmd_tcp ──► 立刻多发一拍
    │
    │                         50 Hz 线程：servol(_cmd_tcp)   ← 同一目标再发
相机回调 ──► 最新 raw 覆盖 ──► worker 720p→128 ──► cache
    │
env.step / recorder 只拷 128×128、组 transition
```

### 2.1 代码

| 文件 | 行为 |
|---|---|
| `hilserl_wa2/ros_adapters/servo_session.py` | `_publisher_loop` 按 `control_dt=0.02` 发 `_cmd_tcp`；`apply` 内积分；`dry_run` 不起线程 |
| `hilserl_wa2/ros_adapters/image_monitor.py` | rospy 只入队 raw；worker decode/resize |
| `hilserl_wa2/envs/wa2_env.py` | 相机超龄**不停** ServoL；状态超龄 / 奇异 / `PROTECTED` 才停 |
| `hilserl_wa2/scripts/record_r11_demos.py` | CTRL 节流（故障 / PROTECTED / 跟踪超差，或每 50 步） |

护栏（保留，第二刀不要删）：

- `PROTECTED` / `cmd_num==15` → `_fault_stop`（stop+clear，停发布线程）
- 指令 TCP 与实测 **>1.5 cm** → 停积分，禁止目标飞走
- 发布线程自己也查上述两项

解锁：停采集 → `rosservice call /zj_humanoid/upperlimb/unlock "{}"` → R5 reset。禁止带着约 10 cm 偏差继续发 ServoL。

### 2.2 真机结论（live20）

- `cmd=SERVOL`，`pub_n` 随时间涨（约每个 `env.step` 对应 3 次 ServoL）→ 线程在跑。
- 跟踪中位约 0.5 mm；图像年龄约 15 ms。
- `env.step` 中位仍 **~32 ms**，16% **>100 ms**，最大 **223 ms**。
- 满杆时一步仍只积 1 mm → 慢步像顿、快步像窜（约 5～100 mm/s 跳）。

**第一刀解决了「指令流中断 / watchdog」；没有解决「跟手匀速」。**

单测（容器，第一刀后）：`test_servo_session`（含 hold-last 快于慢 apply）、`test_image_preprocess`、`test_wa2_env` 共 26 项 OK。

## 4. 第二刀（已落地代码）：latch 动作 + 50 Hz 按时间积分

### 4.1 目标

对齐独立遥操的时间语义：**满杆 ≈ 1 mm / 20 ms ≈ 50 mm/s**，而不是「每个 Gym step 1 mm」。

采集循环可以继续慢（深拷图）；手臂速度由 50 Hz 线程决定。

### 4.2 目标环

```text
Joy 回调 ~30 Hz          只更新最新杆量
Intervention.action()    算出归一化 6D，写入 session latch（加锁）
        │
        ▼
50 Hz 线程（唯一 servol）
  每 20 ms：
    action = latch（无输入则为 0）
    _cmd_tcp = integrate(_cmd_tcp, action)   # 每拍最多 1 mm / 0.25°
    servol(_cmd_tcp)
    查 PROTECTED / 跟踪 / 奇异
        │
        ▼
env.step                 不再在这里 integrate
  更新 latch（policy 或干预）
  拷 obs、返回本间隔内实际积分统计
recorder                 记 latch 的 6D 作为 transition.actions
```

与第一刀的唯一本质差别：线程积的是 **当前 6D 动作**，不是 **上一次算死的位姿**。

### 4.3 建议改动点

**`WA2ServoSession`（主改）**

- 增加 `_latched_action`（6D，默认 0），与 `_cmd_tcp` 同一把锁或并列锁。
- `apply_normalized_action`：**只更新 latch + 安全预检**，不要在这里 `integrate` 一整步（或保留 dry_run 同步积分以便单测简单，live 路径走线程）。
- `_publisher_loop`：每拍 `integrate_normalized_action(_cmd_tcp, latched, contract)` 再 `_publish_pose`。
- `dt` 用线程自己的 `contract.control_dt`（0.02），不要用 `env.step` 墙钟。
- `health()` / `apply` 返回值增加：本步或本拍的 `delta_pos_*`、`publish_count`、可选 `ticks_since_apply`。
- `dry_run`：仍不起真机线程；单测可在 dry_run 里同步积一步，或注入 FakeArm 测「慢 apply、快时间 → 积分次数跟 50 Hz 走」。

**`WA2SpacemouseIntervention`**

- `processor.update(..., dt=)` 改为墙钟 `min(now-last, max_dt)`，不要写死 `control_dt=0.02`（遥操已是墙钟 dt）。
- `action()` 输出的 6D 仍 clip 到 `[-1,1]`，再交给 `apply` 去 latch。

**`WA2Env.step`**

- 仍是唯一运动出口。
- `info["delta_pos_m"]` 等：用「自上次 step 以来线程真实积了多少」（差分 `_cmd_tcp` 或累加器），不要假装「本 step 一定 1 mm」。
- 相机超龄不停 ServoL（已做）保持。

**`record_r11_demos.py`**

- 不必为手感加 sleep。
- `actions` 继续记干预 6D（hold 期间每条 transition 可以是同一 latch，物理位移随 step 时长变长——这是速度指令语义，见 §4.4）。

### 4.4 记盘 / HIL 语义（必须写进提交说明）

| | 现在（第一刀） | 第二刀 |
|---|---|---|
| action=1 的一步 | 永远约 **1 mm**（速度随 `step` 帧率变） | **满速 hold**，150 ms 的一步约 7～8 mm |
| 满杆速度 | 7～30 Hz × 1 mm | **≈50 mm/s**（与契约 50 Hz×1 mm 一致） |

R11 policy 是 zero，示范 `actions` 来自 SpaceMouse，速度语义更接近「杆量」。R13 HIL：策略每 `env.step` 出一个 6D，线程 hold 到下一步——标准 hold-last，比「慢一拍才挪 1 mm」更接近 `control_dt=0.02`。

不要用「一步永远 1 mm」作为第二刀的回归标准，否则手感回不去。

### 4.5 建议实现顺序（代码已合入；真机仍按此顺序）

1. **单测先红后绿**（FakeArm + `R4_CONFIRM=YES`，无真机）：  
   - 慢 `apply`（例如每 100 ms 才 latch 一次满 X）时，`publish_count` 与 **积分次数** 仍约 50/s，TCP 指令以约 1 mm/20 ms 前进。  
   - `dry_run` 不起发布线程。  
   - `PROTECTED` / 跟踪超差仍 fault。  
2. 容器跑 `test_servo_session`、`test_wa2_env`、intervention 相关单测。  
3. 真机：停 teleop；`unlock` 如需要；`--successes-needed 1` 且 **`--out-name` 不要用 live20 前缀**（例如 `wa2_sm_vel_smoke`），stdin 用真实 tty。  
4. 手感：推住满杆，速度应稳定在几十 mm/s，不再 5 mm/s↔100 mm/s。CTRL 连续推动时应看到约每 20 ms 量级的 `dxyz`，而不是每 100～150 ms 才跳 1 mm。  
5. 通过后再考虑是否重采正式 demo（**已落盘的 live20 不必为手感作废**；R13 仍可用今天的 `demo.pkl`）。

### 4.6 验收清单（第二刀）

- [ ] 采集与（未来）HIL 走同一 `WA2Env.step` latch 路径
- [ ] 不覆盖 `wa2_bottle_pick_20_success_440eccc2`
