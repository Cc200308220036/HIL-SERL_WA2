# HIL-SERL-WA2：控制卡顿修复方案

## 1. 文档目的

本文针对阶段三时间尺度（`wa2-r13-timescale-v2`）落地后，**示范采集与 HIL 人工干预仍明显卡顿、不跟手**的问题，给出根因分析、推荐改造路径、分阶段实施流程与验收标准。

本文是后续改代码与真机验收的依据。**本次仅输出方案，不包含代码实现。**

相关文档：

- 《时间尺度改进.md》：高低层 10 Hz / 50 Hz 契约（必须保持）
- 《时间尺度改进测试指令.md》：阶段三 Actor/Learner 验收流程
- 《R13_方案.md》：训练与示范主流程

## 2. 问题陈述

### 2.1 现象

在 Orin Actor 真机上：

- SpaceMouse 进入会话后，手臂运动呈周期性顿挫，手感明显弱于专用遥操；
- 日志常见 `CTRL dt≈110–130 ms`，外环仍约 10 Hz；
- 即使已做 T3-05「窗内 50 Hz 重采样人工动作」，卡顿仍明显；
- 后续 HIL 训练干预走同一执行栈，**同类不跟手会复现**。

### 2.2 非目标误解

| 误解 | 澄清 |
|---|---|
| 「把 Servo 降回 10 Hz」 | 已否决；底层必须保持约 50 Hz |
| 「卡顿会让策略学会故意抖停」 | 一般不会学成显式「停走」技能；学的是 10 Hz 决策 |
| 「只再调 SpaceMouse 滤波就能根治」 | 滤波不是主因；主因是步间隙死区 |
| 「训完策略就会像 50 Hz 遥操」 | 即使学得很好，部署仍是 10 Hz 换动作；丝滑取决于执行环 |

### 2.3 与训练质量的关系

- **Replay 语义**：每条 transition 仍对应约 100 ms 高层窗；示范仍可用于 timescale-v2 训练。
- **策略输出形态**：自主策略天然是「约每 100 ms 换一次连续动作」的台阶运动，这是阶段三设计，不是 bug。
- **额外顿挫**：若 Actor 在窗与窗之间串行阻塞（分类器/观测/日志），自主跑也会叠一层「停一下再动」。这是**执行死区**，不是网络权重里学会了卡顿指令。
- **结论**：现有卡顿 demo **可以开训**；若验收要求「采集/干预/自主都明显跟手」，必须按本文改造执行环，单靠多训无法根治。

## 3. 现状基线（改造前）

### 3.1 已具备（阶段三 + T3-05）

```text
protocol_version            = wa2-r13-timescale-v2
transition_schema_version   = r13-timescale-v2
policy_hz                   = 10
servo_hz                    = 50
servo_ticks_per_action      = 5
episode_max_steps           = 600   # 约 60 s；曾用 250 过短
```

- 策略动作：有限 tick 窗口 `execute_action_window`，恰好最多 5 tick，禁止泄漏到第 6 tick。
- 人工接管（T3-05 已做部分）：
  - 策略窗内左键可中途取消；
  - 人工窗内可通过 `action_provider` 每 tick 重读 SpaceMouse；
  - `intervene_action` 使用窗内动作均值聚合。
- 分类器：默认在高层 `step` 边界推理，`consecutive_n=1`。

### 3.2 仍存在的执行结构

当前主循环本质是**串行 10 Hz step**：

```text
采样/决定动作
    → 阻塞执行最多 5 个 Servo tick（约 100 ms）
    → 窗口结束，latch 清零
    → 取观测 / 分类器 / 构造 transition / 日志（数 ms～数十 ms）
    → 才开始下一窗
```

窗内跟杆改善后，**窗间死区**成为体感卡顿的主因：人还在推杆，臂在间隙内接近零速度保持，再突然接上下一段。

### 3.3 关键代码位置（实施时）

| 模块 | 路径 | 与卡顿关系 |
|---|---|---|
| Servo 窗口 | `ros_adapters/servo_session.py` | 窗结束清 latch；发布线程 50 Hz |
| Env.step | `envs/wa2_env.py` | 阻塞等待整窗；步边界才返回 |
| 干预 | `interventions/wa2_spacemouse_intervention.py` | 人工 provider / 取消 |
| 分类器 | `wrappers/reward_classifier.py` | 步后同步推理，拉长间隙 |
| 采集 | `scripts/record_r13_demos.py` | 每步分类器 + 日志 |
| 训练 Actor | `scripts/r13_actor_train.py` | 策略推理 + 上传与 step 串行 |

Learner **不驱动** Servo；本方案改造重心在 Actor。若协议/transition 字段有增补，Learner 仅做兼容与 manifest 校验。

## 4. 根因分析

### 4.1 主因：高层串行步间隙

| 因素 | 作用 |
|---|---|
| `execute_action_window` 阻塞返回 | 主线程在整窗结束前不能做下一动作 |
| 窗末 latch 清零 | 间隙内无法延续人工速度命令 |
| 分类器 / 图像整理 / 日志 | 叠在间隙上，`CTRL dt` 常 > 100 ms |
| 策略推理（HIL 非干预段） | 同样造成窗间空隙 |

### 4.2 次因（加重体感，非根因）

- 单 tick 增量约 1 mm / 0.25°，即使连续也会偏「沉」；
- SpaceMouse 滤波（`translation_filter_tau` 等）带来轻微滞后；
- 上传 backlog / GIL 偶发拉长个别 step（Mechanism A latch hold 已部分防护）。

### 4.3 已排除或不应采用的「假修复」

1. 把 `control_hz` 降到 10：破坏运动连续性与安全响应。  
2. 把 `policy_hz` 改回 50 且一步一 tick：退回阶段三之前，与论文折扣/episode 尺度冲突。  
3. 仅增大 `action_gain`：更快但更冲，不消除停走感。  
4. 假设「多采卡顿 demo 策略会自己变顺」：部署环不变则自主仍可能顿。

## 5. 目标与约束

### 5.1 目标

在**不破坏** timescale-v2 契约的前提下：

1. **人工会话**：接近连续 50 Hz 跟杆，消除可感知的窗间停走；
2. **策略段**：底层 Servo 连续，高层仍约每 5 tick 换动作 / 产 1 条 transition；
3. **安全**：左键接管 ≤ 2 tick；故障 / 急停立即 hold；禁止双发布者；
4. **数据**：transition 时序可审计；obs / action / next_obs 归因明确。

### 5.2 硬约束（一票否决若违反）

- `policy_hz=10`、`servo_hz=50`、`ticks_per_action=5` 语义保持；
- 一条 transition 对应一个高层动作区间（可被中途截断）；
- 不得恢复旧 50 Hz-only transition 混训；
- 不得在无 `R4_CONFIRM` 时做真机非零运动验收。

### 5.3 成功时的体感预期（合理上限）

- 人工：接近专用遥操，允许极轻台阶，但不应有明显「停一下再动」；
- 自主策略：仍是 10 Hz 换向的平滑台阶，**不是** 50 Hz 遥操丝滑；但不应在每次推理空隙明显刹停。

## 6. 推荐方案：方向 A — 流水线 / 预取

### 6.1 核心思想

```text
时间 →

Servo 50 Hz:  [==== 窗 N 执行 ====][==== 窗 N+1 执行 ====][==== ...
主线程并行:        观测/分类器/策略预取 N+1     观测/预取 N+2 ...
```

- 窗 N 执行期间，准备好窗 N+1 的动作（人工：持续跟杆；策略：推理得到下一动作）；
- 窗 N 一结束，**立即**装载 N+1，消灭死区；
- 高层仍「每 5 tick 切换动作标签并记账」，不是把策略改成 50 Hz。

等价描述：从「**10 Hz 串行 step**」改为「**50 Hz 连续执行 + 每 5 tick 更换高层动作**」。

### 6.2 为什么选 A

| 方案 | 手感 | 改动量 | 与 timescale 一致性 | 推荐 |
|---|---|---|---|---|
| A 流水线/预取 | 高 | 大 | 高 | **主方案** |
| B 仅人工间隙不停 + 分类器降频 | 中 | 中 | 高 | 阶段 1 过渡 |
| C 人工独立 50 Hz 遥操环，RL 旁路采样 | 人最高 | 大（双路径） | 中（两套逻辑） | 备选 |
| D 调增益/滤波 | 低 | 小 | — | 不作为主方案 |

### 6.3 架构要点

1. **单一 Servo 发布线程**继续作为唯一运动出口。  
2. **动作队列或双缓冲**：当前窗 + 下一窗动作；禁止两窗同时 integrate。  
3. **人工模式**：发布线程每 tick 调 `action_provider`；主线程只做观测/分类器/记账，不再阻塞「等人推完 100 ms 才读杆」。  
4. **策略模式**：在窗 N 的后半段或固定 tick 触发异步推理，结果写入 N+1 槽；若推理未完成，安全策略为 hold 上一动作或零速（需在方案实施时二选一并写死，推荐：**短时保持上一动作 ≤ 1 窗，超时则 hold 零速并打点**）。  
5. **中断**：左键 / 安全故障清空队列并立即零速；已预取的策略 N+1 作废。  
6. **Transition 边界**：以「第 k 个高层动作区间」切分；`next_obs` 取该区间结束后的首帧可用观测；人工均值动作规则与现 T3-05 对齐。  
7. **分类器**：允许在窗执行期间异步跑；成功事件打到「当前正在执行的高层区间」；命中后取消剩余 tick（与《时间尺度改进》异常表一致）。

### 6.4 不在本方案一次做完的内容

- 不改底层固件 / ServoL 协议；
- 不把 discount 改回 50 Hz 语义；
- 不自动转换旧卡顿 demo（见第 10 节）；
- 不把 Learner 训练循环改到 Orin。

## 7. 分阶段实施流程

整体原则：**先止血（人工），再流水线（策略），每阶段必须过验收才能进入下一阶段。**

```text
阶段 0  冻结基线与指标
   ↓
阶段 1  人工路径减死区（过渡 B，可快速改善采集/干预手感）
   ↓
阶段 2  方向 A 执行内核（连续 50 Hz + 高层切换）
   ↓
阶段 3  策略预取接入 Actor 训练环
   ↓
阶段 4  分类器异步与成功截断对齐
   ↓
阶段 5  数据/协议/文档与正式采集、训练门禁
```

### 7.1 阶段 0：冻结基线与指标

**目的**：用数字定义「现在有多卡」，避免改完只靠主观感觉。

**动作**：

1. 固定软件版本、`config_bundle_hash`、场景 `max_steps=600`。  
2. 写只读测量脚本（或临时日志）记录每个高层步：
   - `execution_duration_s`
   - `inter_step_gap_s`（上一窗结束 → 下一窗开始）
   - `servo_ticks_executed/requested`
   - `interrupted_by`
   - 人工会话标志 `sm_session`
3. 采 30～60 s 人工会话基线（低尺度、安全区）。

**退出标准**：基线报告归档。Phase0 实测修正：轻量栈 gap≈0；record 栈死区主要在 `post_exec`（同步分类器）与 `transition`，用 `arm_idle_s` 作代理（见 `调试日志/0827调试日志.md`）。

### 7.1b 已落地：分类器降频 + transition 出关键路径（2026-08-27）

在完整阶段 1 latch / 阶段 2 连续窗之前的最小止血：

| 项 | 默认 | 环境变量 |
|---|---|---|
| 分类器模式 | `decimate`（会话内每 2 高层步推理一次） | `WA2_CLASSIFIER_INFER_MODE=sync\|decimate\|async` |
| 会话步距 | 2 | `WA2_CLASSIFIER_SESSION_EVERY_N` |
| 全局步距 | 1 | `WA2_CLASSIFIER_INFER_EVERY_N` |
| Transition | `TransitionPipeline` 与下一窗重叠 | `record_r13_demos` / `r13_actor_train` live |

`async` 可选；成功检测可能滞后约 1 窗。验收仍用 `measure_stutter_baseline.py --stack record`。

### 7.2 阶段 1：人工路径减死区（过渡方案 B）

**目的**：在完整流水线之前，先让**采集与 HIL 干预**可接受。

**建议改动（实施时）**：

1. 人工 `sm_session=1` 期间：窗结束**不要**把有效速度命令清成长期零速；改为保持「最后人工命令」直到下一窗 provider 接上，或直接背靠背启动下一人工窗。  
2. 人工会话内分类器：降频（例如每 2～3 个高层步）或异步；失败则回退同步但打印警告。  
3. 采集日志降频，避免每步重打印拖慢主环。

**不改变**：策略窗仍可先保持串行（本阶段以人控为主）。

**退出标准**：见第 8.2 节「阶段 1 验收」。

### 7.3 阶段 2：方向 A 执行内核

**目的**：Servo 层支持连续窗切换与下一动作预装。

**建议改动**：

1. `WA2ServoSession` 增加「连续窗口」模式：`submit_window(action|provider, ticks=5)` 可在当前窗结束时无缝衔接。  
2. 明确状态机：`Idle / WindowActive / Fault / Hold`。  
3. 单元测试：dry-run / fake publisher 下连续 20 窗，窗间 gap≈0（允许 ≤ 1 个 control_dt）。  
4. 保持 latch 年龄防护仅用于非窗口/故障路径，避免与连续窗冲突。

**退出标准**：见第 8.3 节。

### 7.4 阶段 3：策略预取接入

**目的**：非干预时也消灭「推理空隙刹停」。

**建议改动**：

1. Actor 主循环：窗 N 运行时异步 `policy.sample` → 写入 N+1。  
2. 超时与失败策略写死并单测。  
3. 干预切入：清空预取队列，切换 provider。  
4. fake 模式先跑通，再真机低尺度。

**退出标准**：见第 8.4 节。

### 7.5 阶段 4：分类器异步与截断

**目的**：成功检测不制造死区，且不破坏终局 reward 归因。

**建议改动**：

1. 分类器在控制关键路径外异步执行；结果通过线程安全队列回灌。  
2. 成功：取消当前窗剩余 tick；该 transition `reward` 置成功；记录 `success_tick_index`（可选字段）。  
3. 与 `end_episode`、R5 reset 顺序回归。

**退出标准**：见第 8.5 节。

### 7.6 阶段 5：门禁、文档与数据策略

**目的**：防止旧串行卡顿栈与新栈混用。

**动作**：

1. 若 transition/info 增补字段，更新 `transition_schema` 或 sidecar 可选字段，并双端 hash。  
2. 更新《时间尺度改进测试指令》交叉引用本方案验收项。  
3. 决定 demo 策略（第 10 节）后，再允许正式大规模采集 / Session B。

**退出标准**：第 8.6 节全部勾选；负责人签字（或项目日志确认）后才开正式 HIL 长训。

## 8. 验收标准

验收必须从离线 → 影子/低尺度 → 人工手感 → 策略段 → 数据与训练门禁。前一级未通过不得进入下一级。

### 8.1 A0：静态与契约

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A0-01 | 双时钟未破坏 | `policy_hz=10`、`servo_hz=50`、`ticks=5` |
| A0-02 | 单一发布者 | 文档与代码仍声明仅 Servo session 发布 ServoL |
| A0-03 | 协议可区分 | 若行为变更影响数据，有版本或 sidecar 字段可审计 |
| A0-04 | 旧混训仍拒绝 | 缺 timescale 元数据的 demo/ckpt 仍 fail-closed |

### 8.2 阶段 1：人工减死区

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| S1-01 | 窗间间隙 | 人工会话中 `inter_step_gap_s` 均值 ≤ 20 ms，P95 ≤ 40 ms |
| S1-02 | 跟杆主观 | 操作员确认无明显「停走」；可与专用遥操对比 |
| S1-03 | 接管延迟 | 策略→人工仍 ≤ 2 tick（40 ms） |
| S1-04 | 安全 | 急停 / fault 后不再非零 integrate |
| S1-05 | 采集可完成 | `record_r13_demos` 能跑满成功局；`max_steps=600` 仍够用 |

### 8.3 阶段 2：连续窗口内核

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| S2-01 | 离线连续窗 | fake/dry-run 连续 ≥ 50 窗，gap≤1 tick |
| S2-02 | 无第 6 tick 泄漏 | 每窗 executed≤requested；窗切换动作边界可日志证明 |
| S2-03 | 真机低尺度 | 尺度 ≤ 0.3；连续运动无可见停顿；Servo 发布均值 47.5～52.5 Hz |
| S2-04 | Hold 语义 | 主动 hold / 故障后零速，无旧方向滑行 |

### 8.4 阶段 3：策略预取

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| S3-01 | fake 预取 | 非干预段窗间 gap 与阶段 2 同级 |
| S3-02 | 推理超时 | 故意延迟推理时，行为符合写死的 hold 策略，且打点 |
| S3-03 | 干预抢占 | 预取动作在左键后作废；无「人工后又闪一截策略」 |
| S3-04 | 真机冒烟 | Session A 尺度 0.3，3～5 局无碰撞；自主段无每步明显刹停 |

### 8.5 阶段 4：分类器异步

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| S4-01 | 不堵控制 | 人工/策略连续执行时，分类器耗时不进入 `inter_step_gap` 关键路径 |
| S4-02 | 成功截断 | 成功发生后不执行剩余 tick；终局 `reward=1` 归因正确 |
| S4-03 | 误报可处置 | 误报时可急停；reset 路径与现 R5 一致 |
| S4-04 | 与 n=1 对齐 | `classifier_consecutive_n=1` 在异步下行为有单测 |

### 8.6 阶段 5：训练门禁（全部满足才正式长训）

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| S5-01 | 阶段 1～4 全过 | 报告齐全 |
| S5-02 | 两端 hash | Actor/Learner `config_bundle_hash` 与共享源码 hash 一致 |

## 9. 一票否决条件

## 11. 与「策略是否学会卡顿」的结论（写入验收认知）

1. 策略学习的是 **10 Hz 动作决策**，不是 50 Hz 轨迹跟踪。  
2. 窗间死区主要造成**执行体感差**与**动力学噪声**，通常不会学成「周期性输出零动作」的技能。  
3. 部署若仍串行，自主也会顿 → 应报 **执行环未达标**，而不是单纯「模型没训好」。  
4. 方向 A 达标后：人工应明显跟手；自主应为连续台阶，而无系统性步间刹停。
