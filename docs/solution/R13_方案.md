### 1.2 任务成功定义（训练结束 / 评测共用，与 R12 图像定义一致）

一局 **成功** 当且仅当同时满足：

1. 本局从 R5 reset 开始，`reset_ok=True`，`is_singular=False`；
2. 瓶子被抓起并放到目标放置区，稳定直立；
3. 手爪已张开或已离开瓶子；
4. R12 分类器：连续 `consecutive_n=3` 帧 `p ≥ 0.85` → `succeed=True`；
5. **评测时** 操作员目视确认 4 与现场一致（防假阳性过 Gate）。

失败：掉落、碰撞、奇异、超时 `max_steps=4000`、急停、分类器未 succeed、评测时人判定未放好。

## 2. 目标、非目标与 Action 控制权



### 2.1 目标

1. 完整 HIL-SERL 异步闭环：自主执行 → 关键处人纠正 → 双 Buffer → RLPD 更新 → 新参数回 Actor。
2. R12 分类器作为 **唯一任务奖励源**：`rewards∈{0,1}`，成功则 `terminated=True` 并安全 reset。
3. 预训练 ResNet 只做策略/价值视觉编码；Classifier ≠ Critic。
4. 连续 6D 臂用 SAC；离散夹爪用 Grasp Critic（`{-1,0,1}`）。
5. 训练期 SpaceMouse **干预优先**，`actions` 记实执行（含夹爪维）。
6. 训练后 **脱手评测**：无干预、`action_scale=1.0`，独立完成抓放。
7. 断线 / NaN / 奇异 → `stop+clear`，不继续旧策略。



### 2.2 非目标


| 不做                | 原因                                   |
| ----------------- | ------------------------------------ |
| R14 删容器重建镜像       | 训练稳定后再做                              |
| 7 维灵巧手指关节进策略      | 仍用预定义 grasp/release 目标，只学 **何时** 抓/放 |
| 用分类器 FP 当成功刷评测    | 必须人工确认                               |
| 评测期偷偷按 SpaceMouse | 该局作废                                 |
| W&B 作为 Gate 条件    | `--debug` 可关；需要曲线可另开，不阻塞             |
| 把 R12 抽查脚本当训练入口   | `eval_r12_live.py` 只回归分类器，不训策略       |




### 2.3 Action 控制权


| 阶段      | Env   | 臂策略                | 夹爪                | SpaceMouse      | 分类器                   | 物理控制权               |
| ------- | ----- | ------------------ | ----------------- | --------------- | --------------------- | ------------------- |
| fake 预检 | fake  | SAC 计算             | 合成 7D             | 合成干预            | 不加载                   | 无硬件                 |
| HIL 训练  | live  | SAC×scale（爬升至 1.0） | Grasp Critic 或人右键 | **干预优先**（含右键张合） | reward + succeed→done | Actor 唯一 ServoL；人可抢 |
| 脱手评测    | live  | SAC×**1.0**        | 仅策略               | **关闭**（死人手无效）   | 同上，成功即结束本局            | 仅策略；急停仍在人           |
| 故障      | close | —                  | —                 | 松开              | —                     | `stop+clear`        |


夹爪映射（与上游 hybrid 一致）：

```text
actions[6] 经 round 后 ∈ {-1, 0, +1}
  +1  上升沿 → request_hand("grasp")
  -1  上升沿 → request_hand("release")
   0  保持
重复同号不重复调用（边沿触发）
调用必须后台，不得阻塞 50 Hz ServoL
```

人干预时：臂 6D 用人手命令；右键写入 `actions[6]`，保证 Demo/干预 buffer 里是真张合。

## 3. 论文闭环如何接到 WA2



### 3.1 数据流（与论文同一张图）

```text
                    ┌─ 无干预：执行 clip(sac[:6])*scale
Actor loop (低频) ─┤
                    └─ 有干预：执行人手 6D；右键→ actions[6]
         │
         ▼
  50 Hz latch 积分 ServoL（高频，与 JAX/Learner 解耦）
  夹爪 request_hand 异步
         │
         ▼
  Classifier（R12 ckpt）
    p≥0.85 连续 3 帧 → rewards=1, succeed=True, terminated=True
    否则 rewards=0，done 不变
         │
         ▼
  transition（实执行 7D action）
    每步     → actor_env          RL Buffer
    干预步   → 再写 actor_env_intvn  （并入 Demo Buffer）
         │ Agentlace 5588
         ▼
Learner
  Demo Buffer = R11 增广 7D demo  ∪ 在线干预
  RLPD 50/50 → SAC + Grasp Critic
  每 steps_per_update → 5589 publish params
         │
         ▼
Actor callback 替换权重 → 继续执行
```

重点仍然是：少量完整 Demo 解冷启动；在线干预覆盖策略自己会进的错误态；**不是**长期模仿。评测关掉人，看策略是否已能完成任务。

### 3.2 分类器「正常参与」（相对 R12 的打开项）

R12 Wrapper 今天 **拒绝** `end_episode=True`。R13 改为：

```text
训练/评测：end_episode=True（显式传入，默认仍 False 以免旧脚本误开）

succeed = (连续 consecutive_n 帧 p >= threshold)
rewards = 1.0 if succeed else 0.0

若 end_episode and succeed:
    terminated = True          # 供 RL 的吸收态 / 成功统计
    不在 Wrapper 内调用 reset / stop / unlock
Actor 循环见 terminated:
    1) 记录 SUCCESS
    2) 伺服 health 通过才 env.reset()（R5）
    3) health 失败 → stop+clear，本局 FAIL，不盲 reset
```

`env_factory.py`：仅当 `classifier=True` 且调用方传 `end_episode=True` 才打开。R12 `eval_r12_live.py` 保持 false，作为回归。

误判保护：

```text
阈值不得低于 R12 的 0.85
consecutive_n 不得小于 3
评测成功必须「分类器 succeed ∧ 人工确认」
训练中若人看到未放好却 reset：记 FP、急停、本 session 降级复盘，不计入成功曲线
```

### 3.5 Buffer

与论文 / `train_rlpd.py` 相同（方案 A）：

```text
online (actor_env)     每步
demo_buffer            首次：按局 load episodes/epXXX.pkl 插入后序列化到
                       $R13_RUN/demo_buffer_cache/（与 demo_pkl_sha256 绑定）
                       之后同一次实验重启 Learner：直接读缓存，不再 DEMO_EP_LOAD 20 局
                       + 运行中 intvn 步仍 insert 到同一 buffer
RLPD                   concat(online_half, demo_half)
```

20 条真机 RGB demo 的 `demo.pkl` 约数 GB。16GB 笔记本整包 `pickle.load` 会把空闲内存打到几百 MB 并狂用 swap，终端长时间无输出——这是换页，不是死锁，也 **不能** 靠 4060 显存做这一步。验证与训练都只按局加载 `episodes/epXXX.pkl`。已采完、只有整包、没有分局 pkl 的 bundle：在 **Actor（内存够）** 跑 `split_r13_demo_pkl.py`，**不要改 demo.pkl 字节**（握手 `demo_pkl_sha256` 仍对整包文件做流式哈希）。

Learner 启动若打印 `DEMO_BUFFER_CACHE=miss`：仍会按局 insert（约数十分钟）并 `DEMO_BUFFER_CACHE=saved`。之后同一 `$R13_RUN` 重启应打印 `DEMO_BUFFER_CACHE=hit` 并跳过 20 行 `DEMO_EP_LOAD`。换 demo / 换实验换 run 目录；不要的缓存删 `$R13_RUN/demo_buffer_cache`。强制重插：`--rebuild-demo-buffer-cache`。

R11 原包 rewards 为 0。可选：用分类器离线重标 demo 的 rewards（不作为第一刀；第一刀保持 0，靠在线分类器）。若冷启动过慢再做 relabel，并写入 sidecar。

## 7. 常见故障


| 现象                      | 处理                                                                         |
| ----------------------- | -------------------------------------------------------------------------- |
| live 后期 SpaceMouse 严重延迟 | 旧实现每 10 步在控制环里同步 `client.update()`，Learner 在 JAX update 时会堵 数秒。现已后台上传；干预中跳过 SAC sample。重启 Actor 后应看到 `UPLOAD_ASYNC=true` |
| live 刚 `POLICY_VERSION=1` 就 `network_loss` | YAML `network_max_age_s=5` 是 R10 烟测；R13 live 默认抬到 120s。不要改 `local.yaml`。上传失败仍会 fail-closed。不要 `--network-max-age-s 0` 除非明确接受 Learner 挂了还接着跑旧策略 |
| 脱手后爪不动                  | 7D 未进策略或 demo 第 7 维全 0；查 `record_r13_demos.py` 是否真写入 `actions[6]`，禁止用离线增广包 |
| 分类器一闪就 reset            | `consecutive_n` 被改成 1；改回 ≥3                                                |
| 成功画面 reset 撞桌           | reset 前未 stop+clear / 未等手离开；加 hold 再 R5                                    |
| 用 6D 旧 space_hash 握手    | 预期失败；用 7D 新 hash                                                           |
| 评测时按了 SpaceMouse        | 该局作废                                                                       |
| `train_rlpd.py` 直接 live | 缺 7D wrapper / 握手 / R12 ckpt                                               |
| 把 scale=0.2 的短局当论文结果    | 不是本 Gate                                                                   |
| 合同步 7D 发给 ServoL        | Grasp wrapper 必须剥掉第 7 维                                                    |
