# HIL-SERL-WA2 阶段三：控制时间尺度改进方案

## 1. 文档目的

本文定义 HIL-SERL 在 WA2 机器人上的第三阶段任务：将当前近似“策略、环境步、Servo tick、transition 均为 50 Hz”的执行方式，调整为论文所采用的高低层分离时间尺度：

```text
高层策略 / Env / replay transition：10 Hz（每步约 100 ms）
                         ↓
同一个连续机械臂动作保持执行 5 个底层周期
                         ↓
底层 ServoL 发布与安全检查：50 Hz（每 tick 约 20 ms）
```

阶段三的核心不是简单修改一个频率参数，而是建立一条可验证的时序契约：**一次高层动作必须对应最多 5 个实际 Servo tick，并且只生成一条 replay transition**。

本文是实施及验收依据。阶段三代码已于 2026-08-26 完成首轮实现；离线/fake/dry-run 已通过，Orin 容器 ROS 与真机低尺度测试仍须按《时间尺度改进测试指令》验收。

当前实现版本：

```text
protocol_version = wa2-r13-timescale-v2
transition_schema_version = r13-timescale-v2
policy_hz = 10
servo_hz = 50
servo_ticks_per_action = 5
discount = 0.98
episode_max_steps = 250
classifier_consecutive_n = 1
```

## 2. 适用边界

### 2.1 Actor 端

Actor 端位于 WA2 Orin 的 `catkin_ws` 工作区，主要责任包括：

- 采集机器人状态和相机观测；
- 运行策略推理；
- 执行 6D 连续机械臂动作和 1D 离散夹爪动作；
- 处理 SpaceMouse 人工接管；
- 计算/聚合奖励和 episode 终止信息；
- 构造并上传 transition。

阶段三主要改造对象应位于 Actor 端的 Env/Servo 执行链路。Learner 不负责驱动 Servo，也不应通过 Learner 更新频率控制机器人的物理执行频率。

### 2.2 Learner 端

Learner 端位于 `HILSERL_Learner` 工作区，阶段三涉及：

- 使用与 10 Hz transition 相匹配的训练参数；
- 检查 replay buffer 的时间语义；
- 禁止混用旧 50 Hz buffer 和新 10 Hz buffer；
- 使用新时间尺度重新开展离线训练及 checkpoint 评估。

### 2.3 本阶段不包含

- 不通过降低 Servo 至 10 Hz 来实现论文时间尺度；
- 不以动作平滑器替代时间尺度修复；
- 不直接恢复旧 checkpoint 继续新时间尺度训练；
- 不把旧 50 Hz 数据简单每五条抽取一条；
- 不在本阶段改变机器人底层固件或 ServoL 通信协议，除非后续验证证明现有接口无法提供所需执行确认。

## 3. 当前实现基线

## 3.1 当前频率和动作尺度

| 项目 | 当前配置或行为 | 依据 |
|---|---:|---|
| ServoL 控制频率 | 50 Hz | `wa2_env_contract.yaml: action.control_hz=50` |
| ServoL 周期 | 0.02 s | `action.control_dt=0.02` |
| Actor live 默认频率 | 50 Hz | `r13_actor_train.py --control-hz` 默认解析为 50 |
| 单 tick 最大平移增量 | 1 mm | `max_pos_delta_m=0.001` |
| 单 tick 最大旋转增量 | 0.25° | `max_rot_delta_deg=0.25` |
| latch 最大新鲜时间 | 0.08 s | `DEFAULT_LATCH_MAX_AGE_S=0.08` |
| latch 开始衰减时间 | 约 0.04 s | 超过最大年龄一半开始线性衰减 |
| replay transition | 每次 Actor 循环创建一条 | `env.step()` 后立即 `build_actor_transition()` |
| 任务折扣因子 | 0.97 | `configs/tasks/bottle_pick.yaml` |
| 场景 episode 上限 | 4000 step | `configs/scenes/bottle_desktop.yaml` |
| 动作执行 horizon | 未启用 | `act_exec_horizon: null` |

当前 7D 策略动作语义为：

```text
[dx, dy, dz, droll, dpitch, dyaw, grasp]
```

- 前 6D 是归一化连续动作；
- 第 7D 为离散夹爪动作，`+1` 抓取、`-1` 释放、`0` 保持；
- ServoL 只接收前 6D，夹爪由独立 wrapper/服务处理。

## 3.2 当前实际执行关系

当前 Actor 每轮大致执行：

```text
读取 obs_t
→ 策略采样 action_t
→ env.step(action_t)
→ 构造并保存一条 transition
→ 下一轮重新采样
```

`env.step()` 在 live 路径中刷新 Servo latch；独立的 50 Hz Servo 发布线程读取 latch 并积分位姿。Actor 与 Servo 是异步线程，因此当前只能近似理解为：

```text
1 次 action → 约 1 个 Servo tick → 1 条 transition
```

实际并不保证严格一一对应。一个 action 可能：

- 尚未被 Servo 使用就被下一个 action 覆盖；
- 被 Servo 使用一次；
- 因线程调度或 Actor 卡顿被使用多次。

这会导致 replay 中记录的动作与真实执行增量缺少严格对应关系。

## 3.3 为什么不能直接把频率改成 10 Hz

### 直接把 Servo 改为 10 Hz

这会把底层目标更新和安全响应周期从约 20 ms 放慢到约 100 ms，并使运动更阶梯化。若保持当前单 tick 增量，最大速度下降为原来的约五分之一；若把单 tick 增量放大五倍，又会产生较大的单次位姿跳变。因此不采用该方案。

### 只把 Actor `--control-hz` 改为 10

当前 latch 在约 40 ms 后开始衰减、约 80 ms 后归零，而 10 Hz 两次 action 之间间隔约 100 ms。直接降频会形成：

```text
动作执行 → 动作衰减 → latch 归零 → 下一动作到达
```

这可能造成走走停停或加剧抖动，不能作为阶段三实现。

### 仅使用通用 `act_exec_horizon=5`

当前配置要求该字段为 `null`，并且普通 action chunk/repeat wrapper 未必能确认 5 个实际 Servo tick，也容易把中间 reward、提前终止、夹爪边沿和人工接管处理错误。因此阶段三应在 Env/Servo 边界显式实现动作执行窗口。

## 4. 阶段三目标时间契约

## 4.1 正常高层步

每一个高层环境步必须遵循：

1. 在时刻 `t` 获取 `obs_t`；
2. 策略只推理/采样一次，得到 7D `requested_action_t`；
3. 夹爪离散命令最多触发一次；
4. 前 6D 连续动作进入一个最多 5 tick 的 Servo 执行窗口；
5. Servo 每约 20 ms 执行一次，并保留原有每 tick 安全检查；
6. 正常完成 5 tick 后立即撤销本窗口授权，不得继续第 6 tick；
7. 读取窗口结束后的 `obs_(t+1)`；
8. 聚合窗口内 reward、终止、安全和介入信息；
9. 只保存一条高层 transition。

```text
(obs_t, executed_action_t, aggregated_reward_t,
 obs_(t+1), terminated_t, truncated_t, info_t)
```

## 4.2 动作尺度

正常满幅动作连续保持 5 tick 时，理论累计上限为：

```text
平移：1 mm/tick × 5 tick = 约 5 mm/高层步
旋转：0.25°/tick × 5 tick = 约 1.25°/高层步
```

不能把归一化 action 数值直接乘以 5。五倍累计位移来自相同动作被底层分五次安全积分。

## 4.3 连续动作与离散夹爪动作

| 动作分量 | 高层一步内的执行语义 |
|---|---|
| 6D 连续机械臂动作 | 同一动作保持，最多执行 5 个 Servo tick |
| 1D 离散夹爪动作 | 在高层步的有效边沿最多触发一次，不重复调用五次 |

夹爪服务可能持续超过 100 ms，必须单独记录命令是否触发、服务是否成功以及实际手部状态。不得用重复发送五次夹爪命令来模拟 action repeat。

## 4.4 高层 transition 信息字段

至少应能记录或导出：

| 字段 | 含义 |
|---|---|
| `requested_action` | 策略或人工请求的 7D 动作 |
| `executed_action` | 实际归因给该 transition 的动作 |
| `servo_ticks_requested` | 正常为 5 |
| `servo_ticks_executed` | 实际完成 tick 数，范围 0～5 |
| `execution_duration_s` | 动作窗口实际持续时间 |
| `delta_pos_xyz` | 窗口内累计平移增量 |
| `delta_rot_rpy` | 窗口内累计旋转增量 |
| `grasp_command` | 本步实际触发的夹爪命令 |
| `interrupted_by` | `none/success/safety/intervention/stale/manual_abort` 等 |
| `succeed` | 窗口内是否确认成功 |

如执行中发生裁剪、衰减或提前中止，不能把未经修正的请求动作记录为“完整执行了五 tick”的动作。至少必须同时保存请求动作、实际 tick 数和累计增量，保证后续审计可还原。

## 5. 具体实施任务

## 5.1 T3-01：冻结控制时间契约

在开始编码前形成统一配置和接口定义：

- `policy_hz=10`；
- `servo_hz=50`；
- `ticks_per_action=5`；
- 单 tick 位姿增量仍为 1 mm/0.25°；
- 连续 6D 保持 5 tick；
- 夹爪离散动作每个高层步最多触发一次；
- reward 聚合和提前终止规则；
- 人工接管时 transition 的切分规则；
- 过期、故障和没有下一高层动作时的 fail-closed 行为。

配置项必须区分 `policy_hz` 与 `servo_hz`，避免继续使用含义模糊的单一 `control_hz` 表示两种时钟。

## 5.2 T3-02：Servo 层实现有限 tick 动作窗口

Servo 层后续应提供等价于以下语义的能力：

```text
execute_action_window(action_6d, requested_ticks=5)
```

要求：

- 每完成一次实际积分/发布，tick 计数增加一次；
- 正常情况下执行恰好 5 tick；
- 第 5 tick 后 action 自动归零，不得继续第 6 tick；
- 5 tick 期间不能被当前 40/80 ms 年龄衰减误判为陈旧动作；
- 仍保留独立 watchdog，用于执行线程卡死、状态过期和下一动作缺失；
- 每个 tick 都执行奇异位形、固件保护、状态新鲜度、工作空间等安全检查；
- 支持成功、故障、人工接管和手动终止立即取消剩余预算；
- 能返回实际 tick 数、持续时间和累计位姿增量。

推荐使用“有限 tick 预算/令牌”，而不是依靠 `sleep(0.1)` 或放宽 latch 年龄来猜测已经执行五次。

## 5.3 T3-03：Env 层定义一个真正的高层 `step()`

`Env.step(action)` 应负责完整的高层动作窗口：

```text
启动执行窗口
→ 等待正常完成或提前中止
→ 聚合底层信息
→ 获取窗口后的 next_obs
→ 返回一次高层 step 结果
```

Env 不应为五个 tick 创建五条训练样本。需要定义以下聚合规则：

- reward：窗口内任一时刻确认成功，则高层 reward 记为成功；
- terminated：任务成功后立即为真，并取消剩余 tick；
- truncated：安全、观测过期、手动终止等异常触发；
- `next_obs`：使用最后一个已执行 tick/中止时刻之后的有效观测；
- `info`：包含请求数、实际 tick 数、执行时长、累计增量和中断原因。

## 5.4 T3-04：Actor 主循环降为高层 10 Hz 语义

Actor 每次只进行一次策略采样，并在 `env.step()` 返回后构造一条 transition：

```text
1 次策略推理
→ 1 个高层 Env step
→ 最多 5 个 Servo tick
→ 1 条 replay transition
```

如果 `env.step()` 本身已等待约 100 ms，Actor 不能再无条件额外休眠 100 ms。限速逻辑应根据整轮已用时间只补足剩余时间，避免实际策略频率降到约 5 Hz。

Actor 日志至少应周期性输出：

- 实际高层 step Hz；
- 实际 Servo tick Hz；
- 每步实际执行 tick 数分布；
- 动作窗口耗时均值、P95 和最大值；
- 提前中止次数及原因；
- policy、human、grasp transition 数量。

## 5.5 T3-05：人工接管与 SpaceMouse

人工接管仍应具有底层快速响应，不能等待当前 100 ms 高层窗口自然结束：

1. 检测到有效人工意图；
2. 立即取消策略动作剩余 tick；
3. 清零策略动作 latch；
4. 在接管边界结束策略 transition；
5. 新建人工动作区间并记录实际执行动作；
6. 人工退出后重新建立策略高层步。

禁止把“前半段策略动作 + 后半段人工动作”作为同一条纯策略 transition 保存，否则会把人工修正后的结果错误归因给策略动作。

SpaceMouse 原始控制和安全检测可以保持较高频率；进入 replay 时应按明确的高层窗口聚合或在边界处切分。

## 5.6 T3-06：奖励分类器时间语义

当前 `consecutive_n=3` 的物理时间取决于分类器调用频率：

- 50 Hz 检查时，连续 3 次约对应 60 ms；
- 10 Hz 检查时，连续 3 次约对应 300 ms。

推荐保留较高频率的图像/分类器检测，在一个高层窗口内聚合成功事件：

- 任一底层时刻达到确认条件，立即结束动作窗口；
- 高层 transition 的 reward 置为成功；
- 记录成功发生在第几个 tick；
- 不再执行剩余 tick。

如果实现上只能在 10 Hz 高层边界运行分类器，则必须重新标定 `consecutive_n` 和成功阈值，并单独完成误报、漏报和检测延迟验收。

## 5.7 T3-07：Learner 参数与 episode 时间尺度

时间尺度修改后，需要同步检查：

- 论文混合动作任务的初始参考折扣因子使用 `discount=0.98`；
- episode 上限由当前 4000 个 20 ms step 调整为高层 step；
- 现有示范物理时长约 7.64～24.42 s，对应新语义约 77～245 step；
- 初始可将 episode 上限设为约 250 step，即约 25 s；
- replay buffer 容量、训练启动阈值、上传周期、日志周期和 checkpoint 周期需要按“高层 transition 数”重新解释，而不能机械沿用旧 step 数。

折扣因子必须与实际高层步长一起记录到 run manifest/checkpoint 元数据中。

## 5.8 T3-08：旧数据和 checkpoint 处置

旧数据采用约 20 ms transition，新数据采用约 100 ms transition，两者不得直接混合训练。

推荐优先级：

1. 在新时序语义下重新采集示范；
2. 如需利用旧示范，开发专用转换与审计流程；
3. 转换时按 episode 和连续控制区间分组，最多每 5 个旧 tick 形成一个高层样本；
4. 不能跨成功、终止、夹爪边沿或人工接管边界合并；
5. 连续动作应依据窗口内实际累计位移构造等效执行动作；
6. reward 使用窗口内成功事件聚合；
7. `next_obs` 使用该组最后一个实际执行状态之后的观测。

不允许只保留旧数据的第 0、5、10……条，因为这会丢失中间执行量，并把变化中的 SpaceMouse 动作错误解释为恒定保持动作。

新时间尺度启用后必须创建新的 run，不恢复旧 optimizer、replay buffer 或 checkpoint 继续训练。旧数据和 checkpoint 只保留用于对照审计。

## 6. 异常与边界语义

| 场景 | 预期行为 | transition 处理 |
|---|---|---|
| 正常完成 | 恰好执行 5 tick，第 5 tick 后清零 | 一条正常 transition，`executed=5` |
| 第 2 tick 成功 | 立即停止，不执行第 3～5 tick | 一条 terminal transition，`executed=2` |
| 第 3 tick 安全故障 | 立即 hold/stop | 一条 truncated transition，`executed=3` |
| tick 前观测已过期 | 不执行动作 | truncated 或拒绝建样本，`executed=0` |
| 人工在 tick 3 接管 | 立即取消策略窗口 | 策略样本在边界结束，人工动作另行记录 |
| Actor/Learner 网络卡顿 | 窗口结束后不允许继续第 6 tick | hold；不得沿旧方向自由运动 |
| 夹爪服务失败 | 连续臂动作按安全规则处理，夹爪记失败 | `grasp_command` 必须反映实际执行结果 |
| 手动急停 | 立即停止并清空所有预算 | truncated，不自动恢复 |

## 7. 验收标准

验收顺序必须从无运动测试逐步升级，前一级未通过不得进入下一级。

## 7.1 A0：静态配置与接口验收

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A0-01 | 双时钟配置 | 明确存在 `policy_hz=10`、`servo_hz=50`、`ticks_per_action=5` 或等价配置，含义无歧义 |
| A0-02 | 单位与坐标系 | 单 tick 1 mm/0.25°、base/tool 坐标语义保持明确 |
| A0-03 | transition 契约 | 文档和代码接口均定义一条 transition 对应一个高层动作窗口 |
| A0-04 | 夹爪契约 | 明确 1D 离散命令每个高层步最多触发一次 |
| A0-05 | 旧数据隔离 | 新 run 带时间尺度版本标识，启动时拒绝混载旧 50 Hz buffer/checkpoint |

## 7.2 A1：Fake/单元测试验收

以下用例必须自动化、可重复：

| 编号 | 输入场景 | 通过标准 |
|---|---|---|
| A1-01 | 恒定非零动作 | 恰好执行 5 tick，生成 1 条 transition |
| A1-02 | 零动作 | 执行窗口正常结束，无累计位移和漂移 |
| A1-03 | 满幅平移动作 | 五 tick 理论累计约 5 mm，满足数值容差 |
| A1-04 | 满幅旋转动作 | 五 tick 理论累计约 1.25°，满足数值容差 |
| A1-05 | 成功发生于 tick 2 | `executed=2`，无第 3 tick，terminal 为真 |
| A1-06 | 故障发生于 tick 3 | `executed=3`，立即停止，truncated 为真 |
| A1-07 | 人工在 tick 3 接管 | 策略窗口立即终止，不产生混合归因样本 |
| A1-08 | 夹爪 `+1` 保持 | 夹爪服务只触发一次，不触发五次 |
| A1-09 | Actor 停止发送动作 | 第 5 tick 后保持停止，绝不出现第 6 tick |
| A1-10 | 连续运行 1000 个高层步 | 正常步全部为 5 tick/1 transition，无丢 tick、重复 tick 或线程死锁 |

数值测试容差应由 fake 执行精度确定；无噪声 fake 环境建议使用严格浮点容差，不能用厘米级宽松阈值掩盖少执行或多执行一个 tick。

## 7.3 A2：真机只读/影子时序验收

此级不发送非零运动命令，仅采集时钟和状态：

| 指标 | 通过标准 |
|---|---|
| 高层 step 频率 | 10 Hz 目标；稳定运行窗口内均值 9.5～10.5 Hz |
| Servo 发布频率 | 50 Hz 目标；稳定运行窗口内均值 47.5～52.5 Hz |
| 每步 tick 数 | 所有非中断正常步均为 5 |
| 高层动作窗口耗时 | 正常步约 100 ms；P95 建议不超过 120 ms |
| 第 6 tick | 计数必须为 0 |
| 状态/图像新鲜度 | 不违反现有 0.2 s freshness 上限 |
| 日志可追溯性 | 任一高层 step 可关联到其 5 个底层 tick |

若系统负载导致高层频率偶发偏离，不能通过补发多个动作追赶时钟。应记录超时并安全 hold。

## 7.4 A3：真机低尺度运动验收

在操作员、急停和 SpaceMouse 接管可用的条件下，以较小动作尺度开始：

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A3-01 | 单轴正/负方向 | 方向正确，连续运动，无明显 40/80 ms 衰减造成的走停 |
| A3-02 | 五 tick 累计量 | 实际位移/旋转与配置期望一致，误差在设备跟踪容差内 |
| A3-03 | 窗口结束 hold | 没有新动作时不继续沿旧方向运动 |
| A3-04 | 人工接管延迟 | 不等待完整高层窗口；目标响应不超过一个 Servo 周期，最迟不得超过两个 tick（40 ms） |
| A3-05 | 安全故障 | 任一底层 tick 检测到故障即停止，不能执行剩余预算 |
| A3-06 | 夹爪边沿 | 每个离散边沿只触发一次，动作结果与 transition 标签一致 |
| A3-07 | 长时稳定性 | 连续运行不少于 10 分钟，无失控延续、重复第 6 tick、线程阻塞或计数漂移 |

若设备通信自身无法达到 20/40 ms 的接管响应，应记录底层实测上限并重新评审，不能静默放宽指标。

## 7.5 A4：数据与 buffer 验收

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| A4-01 | transition 比例 | 正常运行每秒约 10 条高层 transition，而 Servo 仍约 50 tick/s |
| A4-02 | tick 元数据 | 正常样本 `requested=5, executed=5`；提前终止样本反映实际数量 |
| A4-03 | 轨迹长度 | 与相同物理时长的旧数据相比约缩短至五分之一 |
| A4-04 | 观测边界 | `next_obs` 来自动作窗口结束/中止之后，不是第一个 tick 后的状态 |
| A4-05 | reward 聚合 | 窗口内成功事件不丢失，成功后无后续运动 tick |
| A4-06 | 介入边界 | policy 与 human transition 不混合归因 |
| A4-07 | 夹爪边界 | 抓取/释放边沿数量与真实服务调用数量一致 |
| A4-08 | 数据版本 | run 元数据包含 policy Hz、Servo Hz、ticks/action、discount 和动作尺度 |
| A4-09 | 数据隔离 | 新 buffer 中不存在旧 20 ms transition；转换数据有独立来源标记和审计报告 |

针对现有 20 条示范，若采用合格转换流程，轨迹长度的参考范围约为 77～245 个高层 step、均值约 152.5；实际值可因终止边界和不足五条的尾组略有差异。

## 7.6 A5：Learner 离线训练验收

新时间尺度数据完成后，从新 run 开始训练并检查：

- Learner 与 Actor 对 action、discount 和时间尺度元数据一致；
- 不恢复旧 optimizer/replay 状态；
- 成功奖励能从终点向轨迹前段形成可观察的价值传播；
- Critic 对不同动作的 Q 值区分度较旧 checkpoint 有改善；
- deterministic 动作评估使用 `argmax=True`、`grasp_eps=0`；
- sampled 动作评估与 deterministic 评估分开报告；
- 训练曲线、离线 audit 和 checkpoint 均标注新时间尺度版本。

A5 不要求仅凭离线指标证明真机任务一定成功，但若仍出现 Q 值几乎只集中在终点、动作区分度接近零或 transition 时序无法还原，则不得进入正式在线训练。

## 7.7 A6：真机策略验收

采用分级动作尺度：

1. 首次以较小连续动作尺度验证安全和方向性；
2. 确认策略动作能持续作用完整窗口；
3. 确认机器人不再每 20 ms 随机换向；
4. 逐级恢复正式训练所需动作尺度；
5. 使用确定性策略单独完成评估；
6. 训练态和评估态分别统计成功率、介入率、episode 时长和安全中止率。

通过标准至少包括：

- 无沿旧动作失控延续；
- 无第 6 tick；
- 接管和安全停止满足 A3 要求；
- policy step 与 replay transition 严格一一对应；
- 机器人动作相较旧 50 Hz 随机采样表现出持续方向性；
- 正式训练前由操作员确认动作尺度、工作空间和急停链路。

## 8. 一票否决条件

出现以下任一情况即判定阶段三未通过：

- 仅把 Servo 或 Actor 参数改成 10 Hz，没有显式 5-tick 执行窗口；
- 正常动作可能执行 4 tick、6 tick 或无法确认实际 tick 数；
- 第 5 tick 后仍可能沿旧 action 继续运动；
- 人工接管必须等待 100 ms 窗口结束；
- 夹爪命令在一个高层步内被重复触发五次；
- 一次高层动作产生五条 replay transition；
- transition 的 `next_obs` 不是窗口结束后的状态；
- 成功/安全故障发生后仍执行剩余 tick；
- 新旧时间尺度 buffer 或 checkpoint 无标识混用；
- 通过延长 latch 超时但没有有限 tick 预算来实现动作保持；
- 通过动作平滑掩盖时序错误，而没有修正 action 与实际执行的对应关系。

## 11. 最终完成定义

阶段三只有在以下关系能够通过日志和测试被严格证明时才算完成：

```text
策略约 10 次/s
每个正常策略动作恰好执行 5 个 50 Hz Servo tick
每个高层动作只产生 1 条 replay transition
异常/成功/接管可在任一底层 tick 提前中断
动作窗口结束后绝不继续第 6 tick
```

最终目标是在保留 WA2 底层 50 Hz 运动连续性和安全响应能力的同时，使 HIL-SERL 的策略、折扣、episode 和 replay buffer 恢复到论文使用的约 10 Hz 高层决策时间尺度。
