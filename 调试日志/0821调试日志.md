## 4. 问题 → 原因 → 处理

### 4.1 分类器假阳性（承 0820）→ 上午补数重训

最终训练 run：`20260821_093953_r12_succfix`。  
最终合并包：`wa2_bottle_pick_clf_merged_succ_f5b37cc6`（250 成功 / 361 失败 / 44 ep；`merged_from`: `b89ac60c` + `succfix_1dfa9224`）。

### 4.2 点了左键干预仍「不听指挥」前冲

| 现象 | 原因 | 处理 |
|---|---|---|
| 已进干预仍往前冲至限位 | Joy `max_age` 过期时旧逻辑 **清会话并回落满幅 SAC** | `WA2SpacemouseIntervention`：会话中 Joy 过期 → **零速 hold，保持会话**；打 `SM_SESSION_HOLD_STALE` |
| 状态看不清 | 状态行无 session/intent | Actor 状态行增加 `sess/intervened/intent/axis/ia_norm/joy_age` |

### 4.3 「沿上一帧的轴一直运动」

| 现象 | 原因 | 处理 |
|---|---|---|
| 杆回中后仍沿上一轴滑动 | ServoL **50Hz 速度闩锁**：控环一卡仍积分上一非零指令 | `WA2ServoSession`：`latch_max_age_s=0.06`，超时自动清零 hold |

### 4.4 Actor 跑久后 SpaceMouse 越来越卡

| 现象 | 原因 | 处理 |
|---|---|---|
| 早期 ~40Hz，久后 ~10–15Hz | `QueuedDataStore(50000)` 囤几万条带图 transition；上传序列化抢 GIL；`store count mismatch`（用 pending len 比 Learner replay len） | 新 `DrainingQueuedDataStore`：容量 **2048**、每批 ≤**128**、上传后按 `last_id` **排空**；确认改看 **last_update_id**；积压 ≥512 提前上传；状态行加 `pending_*` / `hz=` |

### 4.5 限位 / `firmware_protected` / tracking / singular

| 现象 | 处理 |
|---|---|
| 臂进保护或跟踪误差过大 | 急停/clear → 回安全位 → **只重启 Actor**（Learner 可继续）；勿带病硬训 |

### 4.6 Actor 重启后策略「好像没用最新 ckpt」

| 现象 | 原因 | 说明 |
|---|---|---|
| 重启后放置观感差不多 | Actor **不读** `checkpoint_*`；本地 init 后等广播；若一直 `sess=1` 人带飞则看不到策略差 | 看 Learner `RESUMED_STEP` + Actor `POLICY_VERSION≥1`；非干预下再评 |

### 4.7 `GRASP_CRITIC_UPDATE=true` 刷屏

| 现象 | 说明 |
|---|---|
| Learner 反复打印 | 探针：hybrid 的 `grasp_critic` 在更新；**不是**「只训手」。臂走 SAC（`critic/actor/temperature`），夹爪走 DQN 式 `grasp_critic`，两边都吃 **RLPD**（online+demo 半 batch） |

## 7. 关键频率与策略参数传输（本实验）

以下为 **当前 R13 Session B 实际用法**（CLI 默认 + `local.yaml` + live 覆盖）。墙钟上的 Learner 更新速率随 GPU/batch 波动，表中「标称」指代码设定的节拍。

### 7.1 总览表

| 名称 | 标称值 | 在哪 | 含义 |
|---|---|---|---|
| 实机 ServoL / 闩锁积分 | **50 Hz**（`control_dt=0.02 s`） | `wa2_env_contract.yaml` + `WA2ServoSession` 发布线程 | 唯一写臂路径；每 tick 最多 1 mm / 0.25° |
| Actor 控环目标 | **50 Hz**（`--control_hz`，live 默认 50） | `r13_actor_train.py` | `env.step` 节拍；跟不上时 `hz=` 会掉到 10～15 |
| 策略采样（非干预） | **与控环同频**（约每步 1 次 SAC sample） | Actor 主循环 | `sess=1` 时跳过 sample，下发零臂动作由 SpaceMouse 接管 |
| SpaceMouse / Joy 新鲜度 | **0.2 s** | `spacemouse/default.yaml` `joy.max_age_s` | 超时 → 会话 hold（不回落 SAC） |
| ServoL 闩锁最大存活 | **0.06 s** | `DEFAULT_LATCH_MAX_AGE_S` | 无新 `apply` 则清零，防「上一轴冲飞」 |
| 经验上传 | 每 **10** 个 Actor step（积压 ≥512 提前） | `upload_every_steps: 10` + 软水位 | ReqRep **5588** 推 transition；每批 ≤128 条后排空 |
| Learner 梯度步 | 连续（有数据即训） | `r13_learner_train.py` | 每 outer step 内 `cta_ratio=2`：先 critic 向，再全量 |
| **策略参数广播** | 每 **50** 个 Learner step | `--steps-per-update 50` | `TrainerServer.publish_network` → **UDP/广播 5589** |
| Actor 收策略 | **事件驱动**（每收到一次广播 `POLICY_VERSION+=1`） | `recv_network_callback` | **不是**按固定 Hz 拉；两广播间隔常 ≫5 s |
| 策略新鲜度看门狗 | live **≥120 s**（YAML 仍写 5.0，勿改 YAML） | `--network-max-age-s` / live floor | 超时久无新权重则 fail-closed |
| SAC 落盘 | 每 **1000** Learner step | `--checkpoint-period 1000` | `checkpoint_1000`…`checkpoint_10000` |
| 开训门槛 | online ≥ **100** | `--training-starts 100` | 之后才 `R13_RLPD_START` 并首次 publish |
| 分类器 succeed | 连续 **3** 帧 `p≥0.85` | `threshold.json` | 约在 50 Hz 控环上 ≈ **60 ms** 坚持 |
| 单局步数上限 | **4000** | `--episode-max-steps` | ≈80 s @50 Hz（实际常更慢） |

### 7.2 Learner 如何传策略参数

1. 训练循环里 `agent.update(...)` 更新 hybrid SAC 参数（臂：actor/critic/temperature；爪：grasp_critic）。  
2. 当 `step % 50 == 0`：`server.publish_network(agent.state.params)`。  
3. agentlace **BroadcastServer** 走 **`broadcast_port=5589`**，把整棵 params 树推给已注册的 Actor（不是 Actor 轮询 HTTP 拉权重）。  
4. 请求/上传通道是另一路：**`request_port=5588`**（握手、r13-status、datastore 上传）。  
5. 磁盘 `checkpoint_*` **不会**自动被 Actor 加载；只有广播（或你以后改成显式 load）才会进 Actor。

### 7.3 Actor 如何收、多久换一次策略

1. `client.recv_network_callback(update_params)` 订阅 5589。  
2. 每收到一包：`agent.state.params` 整体替换，`POLICY_VERSION` +1，并刷新网络看门狗。  
3. **接收频率 = Learner 广播频率** ≈ 每 50 个 Learner 更新一次；墙钟可能是数秒到十几秒一级，取决于 Learner 速度。  
4. 两次广播之间 Actor 一直用**上一版**权重跑；干预时甚至不用策略。  
5. live 下若 **>120 s** 收不到新权重 → `network_loss` fail-closed（YAML 里的 5 s 仅 fake/握手口径，**不要改 YAML**）。

### 7.4 「策略更新频率」在本实验里指什么

易混的三种「更新」：

| 说法 | 实际 |
|---|---|
| Learner 在更新策略 | 每个 Learner step 都在反传；**actor 头**大约每 2 次 critic 更新才训 1 次（`cta_ratio=2`） |
| Actor 换成新策略 | 仅当 5589 广播到达（默认每 50 Learner steps） |
| 臂上动作在变 | 50 Hz 控环 +（非干预时）逐步 sample；与「换权重」不是同一频率 |

### 7.5 现场怎么读日志里的频率健康度

- Actor 状态行 **`hz=`**：控环实测；长期 <20 会明显发卡（查 `pending_env` / 上传）。  
- **`POLICY_VERSION`**：应变大；长期停在 0 → 没吃到广播。  
- Learner **`PUBLISH_COUNT` / `CHECKPOINT_STEP`**：广播与落盘进度。  
- **`pending_env/intvn`**：应多数时候很小（百级内）；冲到上千说明 Learner 消化慢。
