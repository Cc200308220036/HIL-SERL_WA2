# HIL-SERL 多机器人部署工程代码梳理

> 文档版本：v0.1（大框架）  
> 更新日期：2026-09-01  
> 当前机器人：NaviAI WA2  
> 当前阶段：R1～R12 已验收，R13 真机训练与工程收口中  
> 文档定位：帮助开发者读懂工程、识别核心边界，并为后续精简、归档和迁移到新机器人提供总纲。

## 1. 本文先解决什么问题

本工程不是一个单机训练脚本，而是由机器人端 Actor、训练端 Learner、HIL-SERL 算法源码、机器人适配层、实验配置、模型/数据资产和阶段验收代码共同组成的双机系统。

第一轮梳理先回答以下问题：

1. 工程为什么分成 `catkin_ws` 和 `HILSERL_Learner` 两部分。
2. 一次真实 HIL-SERL 训练的数据和控制如何流动。
3. 哪些代码是算法核心、通用框架、WA2 专属适配、任务配置、运维工具或阶段测试。
4. 阅读代码时应按什么顺序进入，而不是从任意脚本逐行阅读。
5. 将来迁移到新机器人时，哪些部分应复用，哪些部分必须重写。
6. 后续精简工程时，哪些内容可以归档，哪些内容不能因“不是入口”而删除。

本文暂不执行删除、移动、重命名、合并或源码修改。逐文件调用关系、类方法细节和最终归档清单将在后续版本继续补充。

## 2. 系统的三个工程边界

### 2.1 Actor：Orin 机器人端

```text
宿主机：Orin
容器：hilserl
Conda：hil-actor
容器工作根：/root/catkin_ws
仓库对应目录：catkin_ws/
```

Actor 是唯一允许接触真实机器人硬件的一端，负责：

- 订阅 ROS1 机器人状态和双相机图像。
- 构造策略 observation。
- 接收 Learner 发布的策略参数并执行推理。
- 将 6D 手臂动作转换为 ServoL 控制窗口。
- 执行第 7 维离散抓取/释放动作。
- 接收 SpaceMouse 人工干预并覆盖策略动作。
- 使用奖励分类器产生稀疏奖励和成功终止信号。
- 保存实际执行的 transition，并上传到 Learner。
- 在状态陈旧、奇异、网络异常、控制故障等情况下 fail-closed。

正式训练入口：

```text
catkin_ws/src/hilserl_wa2/scripts/r13_actor_train.py
```

正式脱手评测入口：

```text
catkin_ws/src/hilserl_wa2/scripts/r13_actor_eval.py
```

### 2.2 Learner：本地笔记本训练端

```text
主机：本地 GPU 笔记本
Conda：hil-learner
工作根：HILSERL_Learner/
```

Learner 不应连接 ROS 或真实机器人，负责：

- 加载初始成功 demo。
- 接收 Actor 上传的普通和人工干预 transition。
- 管理 Online Replay Buffer 和 Demo/Intervention Buffer。
- 按 RLPD 规则混合采样两类数据。
- 更新 6D Continuous SAC 和 1D Grasp Critic。
- 向 Actor 发布最新网络参数。
- 保存 checkpoint、buffer cache、metrics 和状态文件。
- 校验双端 manifest、协议、空间、时间尺度和数据 schema。

正式训练入口：

```text
HILSERL_Learner/src/hilserl_wa2/scripts/r13_learner_train.py
```

调试日志/

后续精简时应把它视为工程档案，而不是普通临时日志。

## 3. 一次 HIL-SERL 训练如何运行

### 3.1 控制与训练主闭环

```text
┌────────────────────── Actor / WA2 Orin ──────────────────────┐
│ ROS状态 + head/wrist图像                                     │
│              ↓                                               │
│ WA2Env → Intervention → Grasp Wrapper → SERL Obs → Classifier│
│              ↓                                               │
│ Learner参数 → Hybrid Policy → 6D手臂 + 1D夹爪                │
│              ↓                ↑                              │
│       SpaceMouse可覆盖策略动作 ┘                              │
│              ↓                                               │
│    ServoL窗口 + 灵巧手命令 → 实际next observation            │
│              ↓                                               │
│       transition组包、分流、本地队列、上传                    │
└──────────────────────────┬───────────────────────────────────┘
                           │ Agentlace
                           ▼
┌──────────────────── Learner / Laptop GPU ────────────────────┐
│ Online Replay Buffer          Demo/Intervention Buffer       │
│             └──────── 50% + 50% batch ────────┘              │
│                              ↓                               │
│       6D Continuous SAC + 1D Discrete Grasp Critic           │
│                              ↓                               │
│             checkpoint / metrics / publish_network           │
└──────────────────────────┬───────────────────────────────────┘
                           └──────── 参数广播回 Actor
```

### 3.2 动作语义

R13 Replay Buffer 中的动作统一为 7D：

```text
[dx, dy, dz, dRx, dRy, dRz, grasp]
 └────── Continuous SAC 6D ──────┘  └ Grasp Critic 1D
```

- 前 6 维是归一化手臂增量动作，范围 `[-1, 1]`。
- 第 7 维只能是 `-1、0、+1`，分别表示 release、hold、grasp。
- WA2 的 ServoL 接口仍只接收前 6 维。
- 第 7 维由 `WA2GraspActionWrapper` 转换为灵巧手命令。
- transition 必须保存实际执行动作，而不是人工覆盖前的原始策略动作。
- 如果 Servo 窗口提前结束，连续动作按实际执行 tick 比例缩放。
- 如果灵巧手命令失败，第 7 维保存为 0，避免产生错误训练标签。

### 3.3 transition 与 Buffer 分流

标准 transition 为：

```python
{
    "observations": observation,
    "actions": executed_action,
    "next_observations": next_observation,
    "rewards": sparse_reward,
    "masks": 0.0_or_1.0,
    "dones": terminated,
}
```

数据分流规则：

| 数据类型 | Online/RL Buffer | Demo/Intervention Buffer |
|---|---:|---:|
| 普通策略 transition | 写入 | 不写入 |
| 人工干预 transition | 写入 | 同时写入 |
| 初始成功 demo | 不经 Actor 在线上传 | Learner 启动时载入 |

`terminated` 表示任务成功等 MDP 终止，此时 `mask=0`；`truncated` 表示超时、安全停止等 episode 边界，但训练 mask 仍为 1。该语义由 `experiments/transition.py` 统一维护。

## 5. `hilserl_wa2` 包的职责分层

Actor 和 Learner 各保留一份 `src/hilserl_wa2`。其中一部分是双端共享语义，另一部分只在 Actor 或 Learner 使用。

### 5.1 `configs/`：实验事实和接口参数

```text
configs/
├── wa2_env_contract.yaml      # observation/action/频率/安全契约
├── tasks/                     # 训练任务与算法参数
├── scenes/                    # reset位姿、容差、episode边界
├── cameras/                   # 相机topic、编码、预处理
├── spacemouse/                # 人工干预映射和手爪目标
└── network/                   # Actor/Learner地址、端口和超时
```

阅读配置时要区分五类概念：

- Robot contract：机器人动作和观测接口。
- Scene：某个现场和任务的复位标定。
- Task：算法、Wrapper 和 observation key 选择。
- Device：相机和 SpaceMouse 等外围设备。
- Network：双机连接参数。

当前多个目录保存了配置副本。后续精简必须先确定唯一权威源，再设计同步或打包机制，不能直接删除任意一份。

### 5.2 `envs/`：机器人环境抽象

| 文件 | 当前职责 | 面向新机器人的意义 |
|---|---|---|
| `contracts.py` | 把 YAML 契约转换为 Gym spaces 和约束 | 可保留契约思想，字段需适配新机器人 |
| `scene_config.py` | 加载 reset、工作区、容差和 episode 配置 | 通用框架可复用，标定数据必须重做 |
| `wa2_env.py` | 组合状态、图像、ServoL、reset、手爪和安全语义 | WA2 核心适配，新机器人需实现同等 Env 接口 |

`WA2Env` 是当前左臂运动的唯一合法出口。任何新机器人迁移也应保持“一个 Env/Executor 独占动作发布权”的原则。

### 5.3 `ros_adapters/`：WA2 硬件与 ROS1 适配

| 模块 | 作用 |
|---|---|
| `state_monitor.py` | 订阅 TCP、关节、速度、手状态和控制器状态 |
| `image_monitor.py` / `wa2_cameras.py` | 双相机缓存、帧龄、同步和读取 |
| `image_preprocess.py` | 解码、颜色转换、裁剪和 resize |
| `servo_session.py` | 50 Hz ServoL、参数设置、stop/clear 和故障闩锁 |
| `reset_executor.py` | hand/waist/neck/arm reset 与结果校验 |
| `mock_robot.py` / `mock_cameras.py` | 无硬件环境和单元测试替身 |

该目录大部分是 WA2 专属代码，也是移植新机器人时最主要的重写区域。算法层不应直接依赖其中的 ROS message 或厂商 SDK 类型。

### 5.4 `interventions/`：人工接管与上传可靠性

| 模块 | 作用 |
|---|---|
| `spacemouse_input.py` | 原始轴值的死区、滤波、主轴选择和归一化 |
| `spacemouse_config.py` | SpaceMouse 配置校验 |
| `joy_watchdog.py` | Joy 新鲜度和断连保护 |
| `pose_integrator.py` | 人工动作的时间积分/平滑 |
| `wa2_spacemouse_intervention.py` | 将人工动作写入 `intervene_action` |
| `end_effector.py` | 灵巧手适配抽象 |
| `actor_upload_queue.py` | 本地序号、待确认队列、批量上传和游标对齐 |
| `spacemouse_wa2_teleop.py` | 独立诊断遥操作，不是正式 Actor 主循环 |

人工干预和上传队列虽然不属于 SAC 算法，但属于 HIL 数据正确性和真机安全核心，不能因为“不是训练网络”而归档掉。

### 5.5 `wrappers/`：把机器人 Env 转换为 HIL-SERL Env

| 模块 | 作用 |
|---|---|
| `grasp_action.py` | 6D Servo 与 7D hybrid action 之间的桥梁 |
| `reward_classifier.py` | 加载分类器、图像预处理、稀疏奖励和成功终止 |

当前 Wrapper 栈由 `experiments/env_factory.py` 固定构造，不应由启动命令随意改变顺序。概念上的内外关系为：

```text
WA2Env
  → WA2SpacemouseIntervention
  → WA2GraspActionWrapper
  → SERLObsWrapper / ChunkingWrapper
  → WA2RewardClassifierWrapper
```

新机器人只要能提供一致的 observation、连续动作、末端执行器结果和 episode 语义，上层 HIL-SERL Wrapper 可以最大程度复用。

### 5.6 `experiments/`：双端共享实验语义

| 模块 | 作用 | 分类 |
|---|---|---|
| `env_factory.py` | 构建统一 Wrapper 栈和 space signature | 核心 |
| `task_config.py` | 加载、校验和哈希 task YAML | 核心 |
| `transition.py` | executed action、done/mask、双 Buffer 分流 | 核心 |
| `async_transition.py` | transition 组包流水线，降低 Actor 控制间隙 | 核心/性能 |
| `actor_safety.py` | 启动门禁、网络 watchdog、参数签名和 fail-closed | 核心/安全 |
| `r10_protocol.py` | 网络配置、manifest、session 基础能力 | 核心协议 |
| `r13_protocol.py` | R13 握手、时间尺度、NaN 和状态检查 | 核心协议 |
| `demo_io.py` | demo schema、流式读写和 episode 校验 | 核心数据 |
| `classifier_io.py` | 分类器样本、阈值、bundle 和指标 | 运维/数据 |
| `demo_grasp.py` | 旧 6D demo 增广成 7D | 历史兼容，可候选归档 |

这是迁移新机器人时最值得优先保留的“通用框架层”。后续应进一步清除其中残留的 WA2 路径假设，使它能依赖抽象接口而不是具体机器人名称。

### 5.7 `scripts/`：入口、运维工具与阶段 Gate 混合区

当前 `scripts/` 同时包含三种性质完全不同的文件：

1. 正式运行入口，如 `r13_actor_train.py`、`r13_actor_eval.py`、`r13_learner_train.py`。
2. 正式运维工具，如 demo 采集、分类器训练、manifest 构建、数据拆分和离线验证。
3. R1～R12 阶段 Gate、dummy server、dry-run 和专项测量脚本。

精简工程的主要动作之一，就是将这三类脚本在目录上明确分开，而不是按文件名中的 R 编号简单删除。

### 5.8 `tests/`：回归能力，不等于阶段垃圾

单元测试中同时存在：

- 通用核心测试：transition、协议、task config、grasp、buffer、classifier schema。
- WA2 adapter 测试：ServoL、状态、相机、reset、SpaceMouse。
- 历史阶段回归测试：R8/R9/R10 等阶段名下的行为冻结。

阶段验收脚本可以归档，但覆盖当前核心语义的单元测试应保留并重新按模块命名。删除全部带 `rX` 名称的测试会丢失协议和数据契约保护。

### 5.9 WA2 Env 核心架构详解

#### 5.9.1 Env 在工程中的位置

`WA2Env` 是 WA2 硬件与 HIL-SERL 算法之间的 Gymnasium 接口层。它不负责 SAC 梯度更新，也不直接决定策略网络结构，而是把 ROS 状态、双相机、ServoL、reset 和灵巧手统一成：

```python
observation, info = env.reset()
next_observation, reward, terminated, truncated, info = env.step(action)
```

完整分层为：

```text
任务/场景/契约 YAML
        ↓
WA2EnvContract：加载常量并构造 Gym spaces
        ↓
WA2Env：reset、step、observe、request_hand、close
        ↓
WA2硬件适配
├── WA2StateMonitor     ROS机器人状态
├── WA2Cameras          双相机
├── WA2ServoSession     ServoL动作窗口
├── WA2ResetExecutor    场景复位
└── NaviController      厂商手臂/灵巧手接口
        ↓
HIL-SERL Wrapper
├── WA2SpacemouseIntervention
├── WA2GraspActionWrapper
├── SERLObsWrapper
├── ChunkingWrapper
└── WA2RewardClassifierWrapper
        ↓
Actor策略 / Learner
```

理解空间时必须区分两层：

- `WA2Env` 原生空间：嵌套 observation 和 6D 手臂动作。
- R13 Wrapper 后的最终策略空间：展平/堆叠 observation 和 7D hybrid 动作。

#### 5.9.2 三种运行模式

同一个 `WA2Env` 支持三种后端，三者保持相同的原生 observation/action space：

| 模式 | 构造参数 | 状态/图像来源 | 是否真实运动 |
|---|---|---|---:|
| Mock | `fake_env=True` | `MockRobot`、`MockCameras` | 否 |
| ROS 只读 | `fake_env=False, read_only=True` | 真实 ROS、真实相机 | 否 |
| ServoL 真机 | `fake_env=False, read_only=False` | 真实 ROS、相机、ServoL | 是 |

初始化入口是 `envs/wa2_env.py::WA2Env.__init__()`。它依次加载 Env contract、scene，构造 spaces，再根据模式选择 Mock 或真实 ROS adapter。只有可运动模式会创建 `WA2ServoSession`。

#### 5.9.3 原生 observation space

配置源是 `configs/wa2_env_contract.yaml`，由 `envs/contracts.py::WA2EnvContract.from_yaml()` 读取，再由 `build_observation_space()` 构造 Gymnasium `spaces.Dict`。

`WA2Env` 原生 observation 为：

```python
{
    "state": {
        "tcp_pose": float32[7],
        "tcp_vel": float32[6],
        "joint_pos": float32[8],
        "hand_joints": float32[6],
    },
    "images": {
        "head": uint8[128, 128, 3],
        "wrist": uint8[128, 128, 3],
    },
}
```

各状态的物理语义和来源：

| 字段 | 内容 | ROS 来源 |
|---|---|---|
| `tcp_pose[7]` | `xyz + quat_xyzw`，位置单位 m | `/zj_humanoid/upperlimb/tcp_pose/left_arm` |
| `tcp_vel[6]` | 三维线速度 + 三维角速度 | `/zj_humanoid/upperlimb/tcp_speed/dual_arm` 的 `left_arm` |
| `joint_pos[8]` | 左侧胸/肩/肘/腕八关节，单位 rad | `/zj_humanoid/upperlimb/joint_states` |
| `hand_joints[6]` | 左手六关节，单位 rad | `/zj_humanoid/hand/joint_states` |

状态订阅、按关节名提取、线程安全缓存和 `0.2 s` 新鲜度检查位于 `ros_adapters/state_monitor.py`。`WA2Env._get_obs()` 从 Mock 或 `WA2StateMonitor` 取得 state，从 camera adapter 取得 images，再统一转换成契约 dtype。

Gym space 中的 TCP `[-2,2]`、速度 `[-2,2]` 和关节 `[-π,π]` 是供 `observation_space.contains()` 使用的保守检查范围，不是机器人机械限位或工作空间安全边界。

#### 5.9.4 双相机 observation

当前 head 和 wrist 都启用：

| 相机 | ROS 原图 | 策略输入 |
|---|---|---|
| head | `720×1280×3 rgb8` | `128×128×3 RGB uint8` |
| wrist | `720×1280×3 bgr8` | `128×128×3 RGB uint8` |

流水线为：

```text
ROS Image
  → WA2ImageMonitor
  → 编码/颜色转换
  → crop + resize
  → uint8 RGB缓存
  → WA2Cameras.get_images()
  → WA2Env observation
```

涉及文件：

- `ros_adapters/image_monitor.py`
- `ros_adapters/image_preprocess.py`
- `ros_adapters/wa2_cameras.py`
- `configs/cameras/head_wrist.yaml`

`WA2Cameras.get_images()` 强制保证 `head`、`wrist` 两个键存在并满足固定 shape，使策略网络结构不因设备临时状态而改变。

#### 5.9.5 策略最终看到的 observation

原生嵌套 observation 还会经过两个上游 SERL Wrapper。

`SERLObsWrapper` 将四组 proprioception 展平成一维向量，并把图像提到顶层：

```python
{
    "state": float32[27],
    "head": uint8[128, 128, 3],
    "wrist": uint8[128, 128, 3],
}
```

维数为：

```text
tcp_pose 7 + tcp_vel 6 + joint_pos 8 + hand_joints 6 = 27
```

当前 Gymnasium `Dict` 的实际 flatten 顺序是：

```text
hand_joints[6] → joint_pos[8] → tcp_pose[7] → tcp_vel[6]
```

该顺序与 task YAML 的阅读顺序不同，但已经进入模型输入和 space hash，不能在没有模型迁移和双端重建 manifest 的情况下调整。

随后 `ChunkingWrapper` 增加 observation history 维。当前 `bottle_pick.yaml` 为：

```yaml
obs_horizon: 1
act_exec_horizon: null
```

所以 R13 Actor/Learner 实际使用的最终 observation space 是：

```python
{
    "state": float32[1, 27],
    "head": uint8[1, 128, 128, 3],
    "wrist": uint8[1, 128, 128, 3],
}
```

前面的 `1` 是 observation horizon，不是训练 batch 维。

#### 5.9.6 原生 6D action space

`WA2Env` 的原生动作由 contract 定义为：

```python
Box(low=-1.0, high=1.0, shape=(6,), dtype=float32)
```

语义为：

```text
[dx, dy, dz, droll, dpitch, dyaw]
```

- 平移增量在 base frame。
- 旋转增量在 tool frame，以右乘方式更新当前姿态。
- 输入必须是有限的 `float32[6]`，随后裁剪到 `[-1,1]`。

`ros_adapters/servo_session.py::integrate_normalized_action()` 将一个归一化动作转换为单个 Servo tick 的 TCP 增量：

```python
delta_pos = action[:3] * 0.0015
delta_rot = action[3:] * radians(0.375)
```

平移和旋转还会分别做向量范数裁剪，因此多个轴同时满幅时，合位移仍不超过 `1.5 mm/tick`，合旋转仍不超过 `0.375°/tick`。

#### 5.9.7 10 Hz策略与50 Hz ServoL的关系

当前时间尺度是：

```text
policy_hz = 10
servo_hz = 50
servo_ticks_per_action = 5
```

一个策略动作在约 100 ms 的 action window 中最多执行 5 次 Servo tick。因此满幅并完整执行时：

```text
单tick最大合位移：1.5 mm
一个高层action最大累计位移：7.5 mm
对应连续满幅速度约：75 mm/s

单tick最大合旋转：0.375°
一个高层action最大累计旋转：1.875°
对应连续满幅角速度约：18.75°/s
```

`WA2ServoSession.execute_action_window()` 负责：

- 限定最多执行 5 tick。
- 每个 tick 前允许检查人工干预/取消。
- 人工控制路径可在 50 Hz 下重新采样动作。
- 记录实际执行 tick 数和窗口平均动作。
- 窗口结束后清零 latch，禁止动作泄漏到第 6 tick。
- action window 超时时 fault-stop。

如果窗口提前结束，`experiments/transition.py` 会按照 `executed/requested` 比例缩放最终保存的前 6 维动作，使 Replay Buffer 更接近实际运动量。

#### 5.9.8 R13为何是7D动作

`WA2Env` 仍只接受 6D，因为 ServoL 只控制机械臂。R13 在外层增加 `wrappers/grasp_action.py::WA2GraspActionWrapper`：

```text
WA2Env原生： [dx, dy, dz, dRx, dRy, dRz]
R13策略：    [dx, dy, dz, dRx, dRy, dRz, grasp]
```

第 7 维离散化为：

```text
+1 = grasp
 0 = hold
-1 = release
```

执行顺序是：

1. 前 6 维进入底层 Env，完成手臂 Servo action window。
2. Wrapper 判断第 7 维是否产生新的抓取/释放边沿。
3. 调用 `WA2Env.request_hand()` 执行灵巧手命令。
4. 成功时保存实际 `+1/-1`；失败时保存 0，并设置 `hand_exec_failed`。
5. 手爪成功后调用 `WA2Env.observe()` 刷新 next observation。

因此当前两层动作空间是：

```text
WA2Env内部动作空间  = Box(-1, 1, (6,), float32)
R13最终策略动作空间 = Box(-1, 1, (7,), float32)
真实ServoL输入       = 前6维
Replay Buffer动作    = 最终实际执行7维
```

Actor 的 `r13_actor_train.py` 和 Learner 的 `r13_learner_train.py` 都以 `grasp_action=True` 构造 Env，保证双端 space 一致。

#### 5.9.9 Wrapper 构造顺序

正式 Wrapper 栈由 `experiments/env_factory.py::make_wa2_environment()` 固定构造：

```text
WA2Env
  → WA2SpacemouseIntervention
  → WA2GraspActionWrapper
  → SERLObsWrapper
  → ChunkingWrapper
  → WA2RewardClassifierWrapper
```

各层对空间/语义的影响：

| 层 | observation变化 | action变化 | 其他作用 |
|---|---|---|---|
| `WA2Env` | 原始嵌套 state/images | 原生6D | ROS、Servo、reset、安全 |
| Intervention | 不改变声明空间 | 声明仍为6D | 用实际人工动作写 `intervene_action` |
| Grasp Wrapper | 不改变 | 6D扩成7D | 手爪边沿和执行结果 |
| SERL Obs | state展平、image提到顶层 | 不改变 | 适配SERL网络 |
| Chunking | 增加history维 | 当前不变 | observation horizon |
| Reward Classifier | 不改变 | 不改变 | reward和terminated |

#### 5.9.10 `reset()` 生命周期

`WA2Env.reset()` 的主要流程是：

```text
清空episode计数和注入状态
    ↓
等待机器人状态与相机ready/fresh
    ↓
读取scene并判断是否执行真实reset
    ↓
关闭旧Servo session，避免MoveJ与ServoL争用
    ↓
WA2ResetExecutor
├── hand reset
├── waist MoveJ
├── neck MoveJ
├── left arm MoveJ
└── TCP/关节容差检查
    ↓
创建并启动新的Servo session
    ↓
读取初始observation并返回
```

contract 默认 `max_steps=400`，当前 `bottle_desktop` scene 覆盖为 600，因此当前任务约为 `600 × 0.1 s = 60 s/episode`。

#### 5.9.11 `step()` 生命周期

`WA2Env.step()` 的主流程是：

```text
输入6D action
    ↓
检查shape和NaN/Inf，clip到[-1,1]
    ↓
根据模式执行
├── fake：MockRobot积分5次
├── read_only：记录动作但不运动
└── live：状态/奇异/固件预检后执行5-tick Servo窗口
    ↓
step_count += 1
    ↓
检查max_steps和Servo fault
    ↓
重新读取状态与图像
    ↓
基础reward=0
    ↓
返回observation、reward、terminated、truncated、info
```

基础 Env 的 reward 固定为 0；R13 稀疏奖励和成功 `terminated` 由最外层 `WA2RewardClassifierWrapper` 产生。

#### 5.9.12 `info`与训练状态的边界

`WA2Env` 还返回大量诊断信息，例如：

```text
is_singular
state_age / image_age
cmd_num / cmd_name
servo_ticks_requested / servo_ticks_executed
interrupted_by
action_clipped
tracking_err_m
servo_faulted
```

这些字段服务于安全、transition修正、人工干预识别、日志和故障诊断，默认不进入策略 observation。不能因为某字段对控制重要，就直接把它加入状态空间；任何 observation 变化都需要同时评估网络结构、旧 checkpoint、demo、space hash 和双端 manifest。

#### 5.9.13 当前口径中需要后续统一的地方

1. `bottle_pick.yaml` 的 `action.mode: left_arm_6d` 描述底层手臂控制，不代表 R13 最终策略是 6D；最终空间由 Grasp Wrapper 扩为 7D。
2. contract 末尾 `appendix_7d.enabled: false` 是早期 6D 阶段遗留说明，与当前 R13 外层 7D Wrapper 的实际状态不一致。
3. `servo_session.py` 和 scene 的部分旧注释仍写 `1 mm / 0.25°`，当前实际生效值是 contract 中的 `1.5 mm / 0.375°`。
4. proprioception 当前按原始物理量展平，没有在 `SERLObsWrapper` 中执行均值/方差归一化。
5. contract 列出 stale image 可导致 truncated；当前 live Servo 预检主要对陈旧机器人状态、奇异和固件保护立即停机，相机 stale 更多进入 `info`。契约和当前代码行为需要在归档前重新统一。
6. 状态 flatten 顺序由 Gym space 结构决定，与 YAML 展示顺序不同，应在新机器人契约和测试中显式冻结。

### 12.5 R13 数据恢复语义仍需收口

当前还需解决上传退出排空、持久队列、唯一 session、checkpoint 与 buffer 同代恢复、classifier 连续异常等问题。在这些问题解决前，不能把旧 Gate 全部移出开发工作区。

## 14. 当前阅读结论

当前项目已经具备完整的 HIL-SERL-WA2 双机主链路。真正值得沉淀的不是某个 R13 大脚本本身，而是以下稳定边界：

```text
算法核心
  ↕
通用Actor/Learner协议与数据语义
  ↕
标准Env、Intervention、Grasp、Reward接口
  ↕
机器人专属状态、动作、reset和安全适配
  ↕
任务配置、设备配置和可追溯训练资产
```

后续精简应围绕这些边界展开：保留可复用核心，将 WA2 固化为参考机器人 adapter，把阶段 Gate 和历史方案移入可追溯归档，并让新机器人只需实现清晰的硬件契约即可接入同一 Actor/Learner 框架。
