### 1.5 R9 脚本不能直接当 R10 入口

不能仅将 R9 命令中的 IP 替换为笔记本 IP，原因是：

## 3. 可复用设计与冻结语义

### 3.1 文件分层与唯一运行位置

R10 文件按职责分层；不得因为双方 AI 助手都能看见整棵目录，就从错误的主机/容器启动脚本。具体归属见 §2.4。

复用原则：

- 换任务：仅更换 `--task <task_id>` 及 task/scene YAML；
- 换机器：仅更换 `configs/network/local.yaml`；
- 换端口/超时：仅改 network profile；
- Actor、Learner 不各自发明协议常量；
- transition 仍使用 R9 `transition.py`，不为 R10 另建 schema；
- 安全退出仍使用 R9 `FailClosedController`、`NetworkWatchdog`、`UploadWatchdog`。

对外统一将 request/upload 超时和 params stale 归一为 `FAULT_REASON=network_loss`，同时保留 `FAULT_DETAIL=server_disconnect|network_stale`。这样验收不依赖两个 watchdog 哪一个先触发，但仍能追溯原因。

### 3.2 network profile 建议 schema

```yaml
schema_version: 1
profile_id: lab_lan
learner_ip: REPLACE_WITH_LEARNER_IPV4
actor_ip: REPLACE_WITH_ORIN_IPV4
request_port: 5588
broadcast_port: 5589
request_timeout_ms: 3000
network_max_age_s: 5.0
upload_every_steps: 10
allowed_actor_cidr: REPLACE_WITH_ORIN_IPV4/32
```

网络配置与 task 配置分离；`bottle_pick.yaml` 不得出现 IP、端口、超时或防火墙字段。

### 3.3 R10 应用层握手

Agentlace 自带 TrainerConfig hash 只能比对端口/request types/version，不足以证明 task 和 model 一致。Actor 建立 Client 后、`env.reset/step` 前必须发 `r10-handshake`：

```json
{
  "protocol_version": "wa2-r10-v1",
  "session_id": "<UTC/run id + random suffix>",
  "task_id": "bottle_pick",
  "exp_name": "wa2_bottle_pick",
  "config_bundle_hash": "...",
  "network_config_hash": "...",
  "space_hash": "...",
  "params_tree_signature": "...",
  "agentlace_version": "0.1.3",
  "agentlace_wheel_sha256": "...",
  "source_tree_sha256": "...",
  "transition_schema_version": "r9-v1"
}
```

Server 必须全字段等值比较，然后返回 `accepted=true` 和 Server manifest。任一 mismatch：

```text
HANDSHAKE=FAIL
ENV_STEPS=0
不接收 transition
不广播 params
真机时 stop + clear
```

### 3.4 source revision 口径（共享白名单，不是整仓）

两端文件集合不同：Learner 没有真机 `ros_adapters`，Actor 没有 `r10_learner_server.py`。  
因此 **禁止** 对整棵 `HILSERL_Learner` 或整棵 `catkin_ws` 做 `source_tree_sha256`。  
也不能把 `configs/network/local.yaml` 算进源码树（机器 IP 会污染「源码一致」；IP 只走 `network_config_hash`）。

`build_r10_manifest.py` 只哈希下面相对 `<ROOT>` 的白名单（posix 路径、排序后逐文件 SHA-256，再对清单做 canonical JSON SHA-256）：

```text
src/hilserl_wa2/configs/**            # 排除 network/local.yaml 与任意 *local*.yaml
src/hilserl_wa2/envs/**
src/hilserl_wa2/experiments/**
src/hil-serl-main/serl_launcher/serl_launcher/**
src/hil-serl-main/examples/experiments/wa2/**
src/hil-serl-main/examples/experiments/config.py
src/hil-serl-main/examples/experiments/mappings.py
```

只收 `.py` / `.yaml` / `.yml`，忽略 `__pycache__`。  
任一端白名单缺目录或相对路径对不上 → `R10_MANIFEST_MATCH: FAIL`，先同步共享文件，不准改握手去「忽略 source」。

另外仍记录：可用时的 Git commit/dirty；`config_bundle_hash`、`space_hash`、`network_config_hash`、`params_tree_signature`、wheel SHA。

握手里的 `source_tree_sha256` 必须等于这份白名单哈希，而不是整仓哈希。

### 3.5 transition 与干预数量

R10 主跑固定：

```text
actor_env              = 1020
actor_env_intvn        = 20
non_intervention_steps = 1000
intervention_steps     = 20
intervention_segments  = 1
synthetic segment      = step [1000, 1020)
```

`actor_env` 是全量 store，因此包含 1000 条非干预 + 20 条干预，总计 1020 条；`actor_env_intvn` 只包含其中 20 条干预 transition。这一口径严格覆盖总纲的“1000 条普通 transition + 一组 intervention transition”。

Server 对每条 transition 计算稳定 content hash，但 content hash 只用于内容对账，不能单独充当“消息唯一 ID”。相同状态/动作可能合法地产生相同 transition，验收以 Agentlace update id、计数和有序 digest 为准：

- Actor local count = Server count；
- Actor latest id = Server last id = `1019`；
- intervention latest id = `19`；
- Actor 与 Server 的有序 transition digest 一致。
- 若要识别真正的重传，transition 必须携带 `session_id + stream + sequence_id`，不得仅依赖内容去重。

### 3.6 Agentlace 传输语义与恢复边界

当前 Agentlace 0.1.3 为“Client 根据 Server last id 发送缺口”，不是持久化 exactly-once 消息系统。R10 冻结为：

- **同一 Server 进程 + 同一 session**：要求 1020/20 不丢不重；
- **Server 进程重启**：旧 session 立即作废，不自动重放、不自动续跑；
- Actor 先把未确认数据 dump 到本地故障目录，然后 fail-closed；
- Learner 重启后生成新 run/server instance id；
- 操作员检查 manifest/ports/robot state，然后手动启动新 Actor session；
- 旧 dump 只能由后续显式 import/dedup 工具处理，R10 不自动混入新 store。

### 3.7 参数广播

R10 Learner Server 在笔记本用 `fake_env=True` 初始化与 task 一致的 SAC agent，并周期广播 `agent.state.params`。不再传递 Orin 文件路径。接收队列容量用几千～2 万，**不要**按 YAML `replay_buffer_capacity=200000` 建满（16G 会先 OOM）。

Actor callback 必须：

1. 计算 params tree signature；
2. 与 handshake 值比较；
3. 成功 `agent.replace(...)`后才记 `network_update_count += 1`；
4. 回报最后接收时间/版本；
5. callback 失败或超过 `network_max_age_s=5` 就 fail-closed。

ZeroMQ PUB/SUB 可能丢失订阅建立前的第一帧，所以 Learner 必须周期重发，不得只 publish 一次。

## 7. 常见故障与禁止绕过

| 现象 | 判定 / 处理 |
|---|---|
| 在 Orin 上 `source activate_hil_learner.sh` 或跑 `r10_learner_server.py` | 跑错仓库；Learner 只允许笔记本 `HILSERL_Learner` |

| `source_tree_sha256` 对不上 | 多半哈希了整仓或算进了 `local.yaml`/真机脚本；改回 §3.4 白名单并同步共享文件 |

| Learner 打不开 Orin params pickle 路径 | 误用 R9 path 协议；R10 应在 Learner 初始化 params |
| `jax 0.4.35` / `jaxlib 0.4.34` | Learner Gate FAIL；修复环境，不降级 Orin |
| `nvidia-smi` 失败或 JAX 无 `CudaDevice` | R10 Learner GPU Gate FAIL；修复驱动/环境，不得用 CPU 结果代替 |
| 5588 通、5589 不通 | 参数 callback 不可能 PASS；查防火墙/监听 |
| 端口对全网开放 | 立即 FAIL；改为 Orin `/32` |
| handshake mismatch 但 Actor 继续 step | 安全门禁缺失，R10 FAIL |
| Server 显示 1000/20 | 仅生成了 980 条非干预；应固定为全量 1020/20，其中非干预 1000 |

| Server 重启后又收到旧 0..N | 旧队列被自动重放，R10 FAIL；使用新 session/空 store |
| 广播第一次未收到 | PUB/SUB slow join；Server 周期重发，不取消 callback Gate |
| 断线后 Actor 继续旧策略 | 立即急停，R10 FAIL |

| `STOP_OK/CLEAR_OK` 缺失 | 不能用“没看到运动”代替停机证据 |

## 8. R10 完成后的项目边界

R10 PASS 代表：


- Learner 可在断网时自动恢复真机控制；
- 未训练 SAC 可以获得真机 Action 控制权。
